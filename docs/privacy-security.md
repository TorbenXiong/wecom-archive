# 隐私、安全与合规边界

## Windows 采集客户端

- 用户运行客户端即发起本次本地采集，界面明确提示仅处理其有权归档的数据。
- 客户端启动后自动发现和准备数据，不注册后台常驻任务；本地极简版只记录告知文案及展示时间，不虚构员工确认。DPAPI 密钥仅用于当前用户后续本地解析。
- 客户端运行时不访问网络，不包含遥测、更新检查、远程字体或远程图片。
- 诊断仅记录版本、阶段、计数、哈希前缀和错误码；不记录消息正文、账号、密钥或绝对私人路径。
- 原始载荷仅进入用户确认导出的客户端 JSON，不进入日志或长期本地浏览库。

## 中央归档服务端

- 服务端只接受通过身份校验且符合 `client-export.v1` 的 JSON；CSV 不可回灌。
- 首期 API 默认仅监听 loopback。对企业内网开放前必须部署 TLS 反向代理并接入组织身份认证。
- 导入失败返回稳定错误码，不向浏览器泄露数据库、服务器路径或内部错误栈。
- 客户端 JSON 的 schema、批次与消息关系、计数和 SHA-256 必须全部通过后才进入归档流程。
- 服务端的聊天浏览、搜索、导出和保留操作均应产生审计事件。

## 授权与同意模型

未来采集批次必须包含：

- `employee_notice`: 员工告知版本、展示时间、确认时间与证据摘要；
- `external_contact_consent`: `granted`、`denied`、`unknown` 或 `not_applicable`；
- `collection_scope`: 数据源、会话范围、时间范围和消息类型；
- `retention_policy`: 策略 id、到期时间与 legal hold 状态。

`denied` 或缺少组织策略时，采集端必须拒绝采集，而不是仅隐藏 UI。

## 数据保留

首期只保留字段和审计事件，不执行自动删除。未来删除任务必须先检查 legal hold，以不可变审计事件记录策略、操作者、范围、计数和批次哈希。

## 威胁模型摘要

- 路径穿越：所有导出名、媒体扩展名和用户选择路径均规范化并验证边界。
- 内容注入：服务端 HTML 全量转义且 CSP 禁止脚本和远程资源；两端 CSV 均处理 `= + - @` 前缀。
- 不完整证据：采集批次保存源 fingerprint、游标、消息/媒体计数及 manifest hash；消息变化新增修订，不覆盖旧证据。
- 密钥暴露：DPAPI CurrentUser、最短内存寿命、日志脱敏、进程探针隔离。
- 源数据竞争：DB/WAL/SHM 成组快照并比较两次元数据，不稳定时停止并提示关闭客户端重试。
