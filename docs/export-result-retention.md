# 导出结果保留与容量保护

带任务记录的归档导出保留已确认的完成、失败和取消结果，避免后续任务挤掉刚完成的记录。请求响应丢失后，工作台仍可通过原任务标识继续查询；查询不到记录不能据此认定文件没有生成。

## 保留规则

每个服务端状态最多保留 64 条后台归档导出记录，生产状态对应一个独占的数据目录。额度包括排队、执行、取消中、结果未知和未过期的终态，不与导入、采集或设备上传的记录额度混用。

完成、失败或已取消的终态记录保留 1 小时，从首次确认该终态时开始计时。终态只记录一次；后续查询、重复取消或迟到进度不会改写已确认结果，也不会延长保留期。

排队、执行和取消中的任务不按时间清除。缺少完成时间或状态锁异常等无法明确判断结果的记录也保守保留；不能因为容量已满就把未知记录当作已结束记录删除。

## 容量满时

`POST /api/v1/exports/start` 登记新任务前清理已过期的终态。若仍有 64 条记录，返回 HTTP 503 / `EXPORT_TASK_CAPACITY_REACHED`，沿用已有错误结构并标记可恢复；本次新任务没有登记或进入输出队列，已有记录及成品不受影响。

容量包含最近一小时内的终态，因此连续生成或结束大量任务后，即使当前没有正在输出的任务，也可能暂时不能创建新的后台导出。应先查询已知任务，并等待记录到期；本规则优先保留结果确认窗口，不通过立即清除最近结果换取新名额。

未过期的相同任务标识重复登记仍返回 HTTP 409 / `TASK_ALREADY_EXISTS`，即使容量已满也不覆盖原记录。继续查询使用原标识，不重新创建导出。

工作台将容量错误识别为明确的登记前拒绝，显示普通业务错误，不据此查询一个未登记的新任务或回退到同步接口。其他不能证明未登记的创建错误，包括带错误码的 5xx 响应，保留原任务标识并按结果未知处理；继续查询只读取原任务。旧服务端创建入口不支持任务接口时，HTTP 404 的原同步导出回退仍保留。

## 过期查询与文件

状态查询和取消请求只检查目标记录是否过期；登记新任务时再清理全部已过期终态。清理仅移除内存中的任务记录，不删除已生成的导出文件，也不修改归档数据。

目标不存在或过期时，状态与取消接口沿用 HTTP 400 / `INVALID_QUERY`。工作台将其作为无法确认原任务结果处理，保留未知状态及原标识；不能把记录不存在当作导出失败、已取消或没有成品的证明。应先核对导出目录和已有成品，再决定是否重新操作。

## 兼容与限制

- 请求与状态响应字段结构、导出文件名和内容格式不变。完成时间只用于服务端内存中的保留判断，不增加状态 API 字段；容量拒绝通过已有错误响应结构返回新错误码。
- 任务记录仍只存在当前服务端进程内存中，重启会丢失；本轮没有持久任务账本，也不自动恢复刷新页面、关闭窗口或重启前的任务列表。
- 1 小时是结果记录的保留窗口，不是任务执行时限。活跃或未知记录可能长期占用额度；本规则不会强制终止写文件线程或为了腾出容量清除未知结果。
- 原有单目录输出互斥、异步排队和协作取消规则继续适用，见 [导出排队与目录隔离](export-queue.md)。旧同步归档及快速本机导出没有因本规则新增后台任务查询能力。
- 没有增加依赖、更改锁文件、数据库结构或版本化归档契约，也没有新增网络目的地。行为说明不代表已完成真实网络中断、原生桌面或 Release EXE 验收，实际验证范围以本轮验收记录为准。
