# 消息深分页与定位

会话消息的相邻翻页使用消息锚点，搜索命中或引用定位后也从目标附近读取对齐的消息页。任意页码跳转保留 OFFSET；前端只保留最近成功页的首尾 ID，不缓存整段历史消息或全部页码。

## 兼容与一致性

`GET /api/v1/messages` 保持原有消息数组响应，并增加三个可选查询参数，必须同时提供：

| 参数 | 含义 |
| --- | --- |
| `anchor_message_id` | 同一筛选范围内已存在的消息 ID |
| `anchor_shift` | `1` 从锚点之后取下一页；`0` 从锚点开始；`-limit` 至 `-1` 先取锚点前相应条数，再包含锚点补齐当前页 |
| `anchor_revision` | 取得锚点时的归档 revision，与归档摘要相同 |

原来的 `offset` 和 `limit` 始终保留。锚点缺失、筛选不匹配、revision 失效，或锚点前不足指定条数时，执行原 OFFSET 查询。缺少部分参数或 shift 越界返回原有查询错误。旧客户端省略新参数时行为不变；旧服务端可忽略新参数并继续按 offset 返回数组。

服务端在同一只读事务中校验 revision、读取锚点、查询前后边界并补充消息资料。顺序使用存储投影中的 `(sent_at, stable_message_id)`，兼容旧修订正文与投影时间不一致的归档，不将正文时间当作游标。查询继续应用原有发送人、文本、类型、时间和附件筛选，不要求新增索引或派生表。

前端在认证令牌、会话、页大小、升降序或归档 revision 改变后失效旧锚点。定位保持真实页码：先获取原来的精确位置，再按页内位置围绕目标读取，避免第二次深 OFFSET；取消、翻页、切换会话或排序后忽略迟到响应。消息定位接口的响应字段和含义保持不变。

## 测量

使用已有工具链和依赖缓存，在 PowerShell 离线运行：

```powershell
cargo run --release --locked --offline -p archive-store --example query-performance-review -- 100000 anchor-probe
cargo run --release --locked --offline -p archive-store --example query-performance-review -- 500000 anchor-probe
```

仅生成临时合成数据库，不发现或读取真实账号。数据经 SQL 构造，不用于衡量生产导入吞吐。半数消息属于同一大群，包含同时间消息；在该会话 80% 位置取 100 条，逐次断言锚点页、定位后消息页与 OFFSET 的全部消息及顺序一致。位置计数同时比较原 OR 条件和当前元组范围条件，验证精确 rank 相同。

2026-11-06、Windows x64、仓库 Release 配置，每项记录首次和 5 次重复样本。以下为预热 P50，单位毫秒；测试和编译未与测量并行。

| 总消息数 / 大群消息数 | 方向 | OFFSET 取页 | 相邻锚点取页 | 定位后的取页 |
| --- | --- | --- | --- | --- |
| 100,000 / 50,000 | 升序 | 1.420 | 0.332 | 0.387 |
| 100,000 / 50,000 | 降序 | 1.924 | 0.202 | 0.213 |
| 500,000 / 250,000 | 升序 | 44.360 | 0.476 | 0.444 |
| 500,000 / 250,000 | 降序 | 72.981 | 0.571 | 0.597 |

锚点获取不在取页计时内：相邻翻页的边界来自已读页，定位后的取页计时也不包含首次精确位置计数。测量包括存储查询、消息反序列化、只读事务及相等断言，不包含 HTTP、人员与引用补全、网络或 React 渲染；首次请求不代表磁盘冷缓存，也不代表生产 SLA。

精确位置计数改为元组范围条件，使现有复合索引直接处理时间和稳定 ID 边界，但仍需遍历匹配范围。50 万规模、rank 为 200,000 时，升序计数的原条件/元组条件 P50 分别为 66.250/67.316 ms，降序为 83.278/53.512 ms；不能宣称所有精确计数均有稳定提速。新路径主要消除了相邻浏览和定位后再次取页的深 OFFSET，不改变精确页码的成本下界。

数据库仍为 v2，四个版本化归档契约、第三方依赖和锁文件均不需要变更。搜索结果列表自身的 OFFSET、筛选计数、导出和首次未访问页码仍有原来的扫描成本。
