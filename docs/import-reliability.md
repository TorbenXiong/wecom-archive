# 导入可靠性

JSON、加密 `.wca` 和工作台本机采集继续复用原有接口、返回结构、归档契约和校验链路。上传仍使用一个导入名额，认证、排队、接收超时和临时文件清理沿用现有行为。

## 一次导入的数据库边界

过去每个消息批次单独提交，随后再提交会话和人员目录；后批次冲突或目录写入失败时，前批次可能已经可见。

现在一次导入的所有批次、目录、修订、FTS 更新、派生统计和批次审计在同一个 SQLite 事务中提交。后批次冲突或目录失败时统一回滚；只有成功后才发送归档 revision 更新并更新采集端上传成功时间。批次逐个消费，不复制整份导入对象。原单批次写入及单独目录更新 API 保留原有行为。

重复导入仍按源消息身份和内容哈希合并；失败后可重新提交原文件。事务变大可能增加 WAL 占用及其他写入等待，需要为大包保留足够磁盘空间；没有降低持久性、跳过校验或增加并行写入以换取速度。

## 附件边界

附件先校验并原子写入内容寻址媒体库，之后提交数据库引用。目标附件已存在或并发发布时，必须核对现存文件的大小及实际 SHA-256；不能仅验证传入字节、路径存在或大小一致就认为成功。发现同大小损坏文件时拒绝导入并保留原文件，不进行静默覆盖。

数据库与文件系统不是一个原子事务。数据库阶段失败时，本次已发布且暂未引用的附件可能保留；不自动删除它们，以免删除并发本机采集正在复用的附件。失败不会使部分消息批次或目录可见，但不能表述为整个数据目录逐字节回滚。当前未实现孤立媒体回收，完整备份会保留这些文件。

## 验证与限制

回归覆盖后批次冲突、目录写入故障、修订/FTS/统计回滚、失败时不通知页面、修复后重试及再次导入幂等，以及已有附件同大小损坏时的拒绝和文件保留。

真实来源隔离归档的实际 HTTP JSON 导入也已通过后批次冲突、目录写入故障、校验值损坏及已有附件损坏演练，并验证全部表内容回滚、重试及幂等。数据范围、结果和清理边界见 [真实演练记录](acceptance/real-backup-import-drill-2026-11-07.md)。

合成归档另已通过提交前后进程强制终止、SQLite 页数上限和新建 256 MiB 虚拟磁盘实际 NTFS 写满演练，覆盖全部表回滚、重新打开后的完整性及重试。物理断电、磁盘缓存丢失和 HTTP/加密上传全过程写满仍未验证；当前 WAL + `synchronous=NORMAL` 的耐久性边界见 [存储故障演练](storage-fault-drill.md)。

工作台支持可选任务标识及导入结果查询；请求响应丢失或出现不确定的带码 POST 错误时，只查询原任务，状态暂不可用时阻止误点重传。明确业务失败继续显示原错误。响应分类、旧端兼容、超时预算、记录保留及远程设备上传的区别见 [长任务状态与超时协调](long-tasks.md)。接收后取消、断点续传及有界内存协议仍未增加；不能把网络错误等同于服务端已回滚。
