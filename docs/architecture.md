# 架构

```text
本机企业微信数据
       │ 只读复制 DB/WAL/SHM
       ▼
source-windows → parser → MessageV1 / ClientExportV1
       │
       ├── 工作台本机采集 ───────────────┐
       │                                 │
       └── 专属采集端 → 可选脱敏 → 上传或离线加密导出 ┤
                                         ▼
                              校验 / 解密 / 幂等合并
                                         │
                                         ▼
                           SQLite/FTS5 / 媒体库 / 工作台
```

## 入口与运行模式

项目发布 `WeComArchive.exe` 工作台。工作台运行归档服务并打开管理界面；服务端按需生成携带签名绑定配置的采集端文件，采集端仍复用工作台的采集运行时。

React 只能调用白名单 Tauri commands。Windows API 和源数据适配集中在 `source-windows`；跨平台的 domain、parser、transfer、archive-store 和 export 不依赖 Windows API。

服务端入口保留公开桌面启动 API，内部按 `runtime`、`state`、`config`、`api`、`collector`、`service`、`auth` 和 `error` 拆分。HTTP 请求与响应类型集中在 `api/types.rs`，采集控制与本机调度分别位于 `collector/control.rs` 和 `collector/local.rs`。Windows 加密、DPAPI 和默认应用打开通过 `source-windows` 的 crate API 调用，不再通过路径包含其他 crate 的源码。

归档存储入口保留原有公开类型和方法，连接、迁移、schema、写入和修订分别位于独立模块，查询按消息、会话、参与人和统计拆分。参数化筛选谓词由消息查询和计数共用；正文与附件名搜索先确定候选消息，避免逐条重复执行 FTS。基准方法与测量边界见 [`benchmarks.md`](benchmarks.md)。

消息分页先按时间和稳定消息 ID 选择索引记录，再读取该页正文。已有 v2 归档在可写打开时以 `CREATE INDEX IF NOT EXISTS` 补建全局时间索引，首次打开需要额外时间与磁盘空间；数据库版本、字段和旧迁移 SQL 保持兼容。OFFSET 接口保留，深分页只跳过索引记录，仍随 offset 增长。

会话列表先按最近消息时间索引选定页，再读取统计与参与人信息。写入将会话最近消息时间合并为每批、每会话一次更新，保持原有字符串最大值及修订投影语义，减少排序索引的反复改写。`archive_conversation_stats` 缓存每个会话的消息数和去重附件数，`archive_conversation_media_refs` 记录会话内同一附件的引用次数；消息和附件关系的触发器在写入事务内维护统计，包括共享附件、修订替换、删除和会话投影迁移。旧库首次可写打开时在同一事务内回填这些内部派生表，后续打开不重复扫描。只读打开尚无派生表的 v2 归档时仍按原表计算，不修改归档。

FTS 保留原表及搜索语义，`archive_fts_rows` 单独索引消息 ID 与实际 FTS 行号；行号不依赖消息表行号，也不访问 FTS 的内部影子表。修订先按映射删除旧 FTS 行，再更新正文、插入新行并记录行号，全部处于批次事务内。旧版本写入会通过消息触发器使相关映射失效，新版本下次处理这些消息时以每批最多一次 FTS 扫描修复映射；正常新版本修订不再扫描整个 FTS。批次写入复用参数化 prepared statements，并将可写连接的语句缓存限制为 32 条，避免逐消息重新编译 SQL 及触发器程序。派生表和触发器均为 v2 的兼容附加结构，不改变四个版本化契约；代价是首次回填、额外磁盘空间和写入维护成本。

## 采集与传输

自动发现合并当前用户企业微信注册表设置、DPAPI 记住的目录和默认目录，统一去重排序，当前数据优先于历史 `Backup`。手动重试只扫描填写的本机子目录，成功后记住；采集端发现、本机采集和后台任务共用此逻辑。

源数据先复制到对应运行端的数据目录，再验证快照并解析，完成或失败后清理。工作台本机采集、快速导出和密钥探针快照使用 `serverData/work/<run-id>/`（配置 `WECOM_ARCHIVE_SERVER_DATA` 时跟随该目录）；采集端使用 exe 同级 `collectorData/work/<run-id>/`。工作台本机采集直接进入本机归档；服务端生成的采集端使用签名绑定配置和 DPAPI 保护的本地缓存上传。

服务端生成采集端时预置设备身份、令牌和目标配置，不要求用户输入服务端地址、注册码或密钥；服务端维护每个采集端的启停、采集选项和计划。控制响应使用 `CollectorControlEnvelopeV1`，包含修订号、15 分钟有效期和服务端签名；采集端只接受签名正确、未过期且不低于本地版本的配置。采集端在启动、任务前后及空闲心跳时轮询控制 API，配置缓存以原子文件保存，并在下一次任务前生效。上传包仍使用随机 AES-256-GCM 数据密钥，并以 RSA-OAEP-SHA256 封装。私钥仅以 DPAPI 保护形式保存在工作台。

工作台可维护多条固定间隔或每日定时本机计划，每个远程采集端维护一条目标计划。采集端启动时已启用计划，或收到从停用改为启用的配置后，立即采集并上传一次；任务锁忙碌时保留首次任务，普通周期无消息变化则跳过上传。调度器与进程同生共灭，采集和上传共用任务锁。本机计划在内部配置中单独保存成功任务的开始时间，下次从该时间前移 5 分钟增量读取，失败不推进游标；升级后的旧配置没有此游标时先全量扫描一次，回补可能遗漏的数据。尝试时间与成功时间分别记录：远程管理页只用成功上传时间展示“最近成功”，本机计划仍使用成功完成时间。

采集端身份由 `collectorId` 和访问令牌确定，心跳不会因来源 IP 相同而删除其他采集端；重新生成后的旧身份由管理员显式撤销。断网、超时和服务端临时错误保留采集端进程，由下一轮心跳重试；只有 HTTP 401 且本产品返回 `UNAUTHORIZED` 时才停止运行。上传和心跳的令牌经匿名管道交给系统 curl，不出现在命令行或临时文件中；请求正文暂存于采集端 work 目录并在请求结束后清理。

工作台在创建窗口前，按本进程服务端页面的精确 origin（含端口）添加运行时 capability，仅授予主窗口退出、检查更新和安装更新三个 commands；局域网和自定义端口不需要扩大静态 URL 白名单。

导出支持独立选择会话时间和会话内容时间的升序/降序：会话时间取会话内最近消息时间，内容时间取单条消息时间。会话工作台的消息顺序由服务端在全量数据上排序后再分页，避免仅反转当前页造成跨页顺序错误。

服务端依次限制请求体、校验身份、验证包与归档契约、解密、持久化媒体、按源消息 ID 幂等合并并记录审计。工作台逐文件校验并原子写入内容寻址媒体库。SQLite 使用 busy timeout 处理并发与异常退出后的短暂锁定；重复消息保持不变，内容变化形成修订。

升级分为工作台和采集端两条路径。工作台手动读取 GitHub/GitLab Release API，只接受 HTTPS、严格的 `x.y.z` 版本、对应 Windows x64 EXE 和 SHA-256 校验值；优先使用 GitHub 资产 digest，缺少 digest 的服务使用同名 `.sha256` 附件。下载后由独立替换助手等待父进程退出，保留旧文件并在新进程未完成启动时回退。采集端升级请求由服务端管理员创建，服务端通过已认证心跳返回签名的 `software-update.v1` 描述；采集端从同一服务端下载当前 EXE，追加现有绑定配置后再走同一替换助手。升级路径不复用归档契约，不暴露令牌到日志。

## 浏览与导出

工作台将会话、参与人、消息、引用和群信息投影到界面。全局搜索结果可定位到原消息；分页后回到顶部，滚动时可跳到顶部或底部。媒体按内容哈希存储，图片通过已认证 API 预览，文件映射为带安全扩展名的本机副本后由 Windows 默认应用打开。归档修订变化后，页面自动重新读取当前会话。

工作台按当前会话、当前筛选或全部档案导出单个 JSON、CSV、HTML 或 Markdown 文件。阅读型 JSON、HTML 和 Markdown 以会话为分组，CSV 保持同一会话连续并带会话字段；本机完整 JSON 仍保留可导入契约，同时附加会话消息视图。导出使用 `.partial` 原子完成并拒绝覆盖已有文件；CSV 防公式注入，HTML 全量转义并禁止脚本和远程资源，Markdown 对结构字符及 HTML 标签进行转义。

归档导出由 `ArchiveExportSource` 和 `archive-export::export_streamed` 连接：在同一个 SQLite 只读快照中先扫描筛选结果、保留会话与参与人元数据，再按筛选后各会话的最近消息时间排序，逐条读取、脱敏并写入文件。简化模式移除公告和看板后重新计算会话时间，附件缺失统计与实际输出核对。脱敏保留相邻消息上下文，隐藏的公告仍能提供上下文；降序输出仅缓冲相邻原消息。旧修订造成正文与索引字段不一致时，仅对受影响会话按正文排序记录键，再逐条读取正文，保持原筛选和输出语义。内存随会话数、参与人数及单条消息大小增长，不再保留完整消息集合。长时间读取会延后 WAL 回收；导出串行执行，避免多个导出同时保留快照。直接采集的本机完整 JSON 仍使用既有可导入契约和采集结果集合；本机阅读型 JSON 的序列化也不再构造完整 JSON 中间对象。

## 版本化契约

`MessageV1`、`ArchiveBatchV1`、`ClientExportV1` 和 `UploadEnvelopeV1` 保持字段语义兼容。采集传输继续使用 `enterprise-package.v1` 作为既有协议版本名，解密后进入 `ClientExportV1` 校验链路；该内部名称不代表独立产品版本。
