# 架构

```text
本机企业微信数据
       │ 只读复制 DB/WAL/SHM
       ▼
source-windows → parser → MessageV1 / ClientExportV1
       │
       ├── 工作台本机采集 ───────────────┐
       │                                 │
       └── 专属采集端 → 可选脱敏 → 上传或离线加密导出 ┤
                                         ▼
                              校验 / 解密 / 幂等合并
                                         │
                                         ▼
                           SQLite/FTS5 / 媒体库 / 工作台
```

## 入口与运行模式

项目只发布一个 `WeComArchive.exe`。正常启动时，它运行归档服务并打开桌面工作台；当程序尾部存在有效的签名采集配置时，同一入口切换到专属采集端界面。两个前端构建目录分别承载工作台和采集端资源，但不对应两个产品或两个发布文件。

React 只能调用白名单 Tauri commands。Windows API 和源数据适配集中在 `source-windows`；跨平台的 domain、parser、transfer、archive-store 和 export 不依赖 Windows API。

## 采集与传输

源数据先复制到系统临时目录，再验证快照并解析，完成或失败后清理。工作台本机采集直接进入本机归档；专属采集端使用自身签名配置中的 URL、凭据、密钥和采集选项上传，不创建 `userData`。

工作台将服务端、上传凭据、公钥、采集选项、计划和员工告知作为签名配置写入采集端 EXE 尾部。采集端启动时验证 RSA-PSS-SHA256 签名；上传包使用随机 AES-256-GCM 数据密钥，并以 RSA-OAEP-SHA256 封装。私钥仅以 DPAPI 保护形式保存在工作台。采集端不接受远程配置变更，修改后需重新生成 EXE。

工作台可维护多条固定间隔或每日定时计划；每个启用计划后生成的采集端形成一条只读记录。采集端首次启动立即采集上传，之后按签名计划运行。调度器与进程同生共灭，单进程内串行采集，避免手动任务与计划任务重叠。计划采集使用带重叠窗口的增量读取，失败不推进游标；执行状态和预计下次时间会回写展示。

导出支持独立选择会话时间和会话内容时间的升序/降序：会话时间取会话内最近消息时间，内容时间取单条消息时间。会话工作台的消息顺序由服务端在全量数据上排序后再分页，避免仅反转当前页造成跨页顺序错误。

服务端依次限制请求体、校验身份、验证包与归档契约、解密、持久化媒体、按源消息 ID 幂等合并并记录审计。工作台逐文件校验并原子写入内容寻址媒体库。SQLite 使用 busy timeout 处理并发与异常退出后的短暂锁定；重复消息保持不变，内容变化形成修订。

## 浏览与导出

工作台将会话、参与人、消息、引用和群信息投影到界面。全局搜索结果可定位到原消息；分页后回到顶部，滚动时可跳到顶部或底部。媒体按内容哈希存储，图片通过已认证 API 预览，文件映射为带安全扩展名的本机副本后由 Windows 默认应用打开。归档修订变化后，页面自动重新读取当前会话。

工作台按当前会话、当前筛选或全部档案导出单个 JSON、CSV、HTML 或 Markdown 文件。阅读型 JSON、HTML 和 Markdown 以会话为分组，CSV 保持同一会话连续并带会话字段；本机完整 JSON 仍保留可导入契约，同时附加会话消息视图。导出使用 `.partial` 原子完成并拒绝覆盖已有文件；CSV 防公式注入，HTML 全量转义并禁止脚本和远程资源，Markdown 对结构字符及 HTML 标签进行转义。

## 版本化契约

`MessageV1`、`ArchiveBatchV1`、`ClientExportV1` 和 `UploadEnvelopeV1` 保持字段语义兼容。采集传输继续使用 `enterprise-package.v1` 作为既有协议版本名，解密后进入 `ClientExportV1` 校验链路；该内部名称不代表独立产品版本。
