# 备份与恢复

支持工作台完整备份、校验、恢复到新目录，以及恢复后的停服检查。备份在独立维护窗口中离线执行；尚未提供定时自动备份、在线备份或跨机密钥迁移。

## 使用维护窗口

1. 等待采集、导入和导出结束，在桌面工作台的“设置 → 归档存储”点击“退出工作台并打开备份与恢复”。工作台停止本机服务，独立窗口不启动服务、采集计划或企业微信源发现。工作台配置损坏而无法启动时，也可直接以维护模式打开同一个程序（PowerShell）：`./WeComArchive.exe --maintenance`。
2. 点击“选择位置并创建备份”，通过 Windows 原生对话框选择服务端数据目录以外的本机目录。程序新建 `WeComArchive-backup-<时间>-<随机标识>/`，不覆盖已有目录。使用 `WECOM_ARCHIVE_SERVER_DATA` 时，备份该变量指定的数据目录。
3. 完成后可用“选择备份并校验”复核文件清单、大小、SHA-256、SQLite 完整性、外键、已验证附件字节及当前用户的 DPAPI 解密能力。备份清单 `backup-manifest.json` 使用独立的 `wecom-backup.v1` 格式；当前只接受与运行程序相同的产品版本。
4. 恢复时先选备份目录，再选择存放位置。程序只创建 `WeComArchive-restored-<时间>-<随机标识>/`，保留原数据和备份，逐文件复制并重新校验，不进行覆盖式恢复。
5. 打开新目录中的 `WeComArchive.exe`，先进入“恢复待确认”窗口。若 `WECOM_ARCHIVE_SERVER_DATA` 仍指向其他目录，程序会停止并提示取消该变量，不会误启动原工作台。确认恢复时再次校验数据和凭据，暂停本机计划、停用旧采集端、清除其待执行采集及升级请求，并将服务端地址重置为本机；首次自动打开也强制使用本机监听。设备撤销记录、身份和密钥保留。进入工作台后重新核对授权、采集端配置和监听地址，再按需启用。以后的启动仍遵循用户显式设置的监听环境变量。

直接打开完整备份目录中的程序也只进入维护窗口，不启动归档服务；此时不提供创建备份或确认恢复操作，需先恢复到新目录。其他工作台若把数据目录指向完整备份内的 `serverData/`，同样拒绝启动，避免把受控备份当作日常运行目录。

维护命令只能由本机维护窗口调用；原生目录选择器决定路径，不向 WebView 开放任意路径、通用文件系统或 shell。浏览器页面不提供维护入口。

工作台和备份操作持有同一数据目录的进程级文件锁。工作台仍在退出或后台任务尚未结束时，备份会拒绝操作，待退出完成后重试。旧版本程序不识别此锁，使用前仍需确认所有使用该目录的旧工作台已经退出；其他外部工具也不应在备份期间修改数据目录。

数据库通过只读连接的 `VACUUM INTO` 生成包含已提交 WAL 页的独立快照，不逐个复制运行中的数据库旁车。其余服务端持久文件完整复制，包括配置副本、媒体、已生成采集端、导出及日志；排除 `work/`、`imports/`、`snapshot-cache/`、数据库 WAL/SHM、工作台锁及恢复待确认标记。另保存当前程序和存在的 exe 同级 `source-roots.dpapi`；远程电脑上的 `collectorData/` 不在本工作台备份范围内。

复制、刷盘和校验都在本次独占创建的 `.partial` 目录内进行，通过后才重命名为正式目录。失败时尝试清理本次目录；文件占用、强制结束进程或断电可能留下 `.partial`，不会被视为已完成备份。程序拒绝从 `.partial` 目录恢复，拒绝链接、junction、路径穿越、重复路径及不符合清单的文件。校验清单用于检测内容缺失或损坏，不提供备份来源真实性证明；备份必须由可信位置保管。

## 备份范围

完整 JSON 导出用于消息契约往返，不是完整备份：服务端导出不包含附件字节，也不能还原服务端密钥、设备身份和计划配置。

| 内容 | 保存范围与作用 |
| --- | --- |
| 服务端数据目录 | 完整保存实际使用的 `serverData/`；设置 `WECOM_ARCHIVE_SERVER_DATA` 时保存该目录。包含 `archive.db`、存在的 WAL/SHM、`media/`、`enterprise-config.json`、`enterprise-config.json.bak`、`access-token.dpapi` 及其他子目录。 |
| 程序 | 保留与备份对应的 `WeComArchive.exe`，便于先用原版本验证恢复，再升级。 |
| 自定义源目录 | 如需保留目录记忆，一并保存 exe 同级 `source-roots.dpapi`。 |
| 采集端 | 如需恢复采集端本地状态，分别保存已绑定采集端 EXE 和完整 `collectorData/`，包括 `instances/`、离线导出等；这些不属于服务端 JSON 导出。 |

备份包含聊天与受 DPAPI 保护的凭据，存放在受控本地目录或受控离线介质，不放入 Git、日志或交付包。`artifacts/<包目录>/` 仍只允许交付单个 EXE。

`snapshot-cache/` 是周期采集的可丢弃原始数据库缓存，可能含未经脱敏的源内容，不是恢复必需文件；备份可排除此目录。停机删除后仅影响下次快照的写入量，不替代归档、媒体、密钥或增量进度。

## 当前离线备份方法

1. 记录程序版本、实际服务端数据目录和所用 Windows 用户，暂停采集计划及上传，正常退出工作台；涉及采集端目录时也正常退出对应采集端。确认进程退出后再复制，备份期间保持停机。
2. 将上述内容完整复制到一个新的备份目录，不覆盖已有备份。数据库旁仍存在 WAL/SHM 时一并复制，不手工删除，不仅复制主数据库文件。
3. 核对相对文件清单、大小和 SHA-256。清单保存在受控备份位置，不输出真实路径、文件名或内容到产品日志和测试产物。
4. 复制和校验全部成功后再将本次备份标记为可恢复。复制中断、文件缺失或哈希不一致的目录不能作为完成的备份。

运行中的逐文件复制不保证数据库、媒体、配置一致。自动维护备份同样要求原工作台停服，不提供在线备份。

## 配置异常恢复

- 每次保存 `enterprise-config.json` 前，先安全保存当前可解析版本到 `enterprise-config.json.bak`，再替换主文件；首次初始化的两份内容相同。副本是上一版配置，可能不包含最新设备、计划或密钥调整。
- 写入使用同目录独占临时文件，完成写入和 `sync_all` 后覆盖重命名，不先删除旧文件。替换失败时保留原主文件，并清理本次临时文件。
- 设置保存成功后才切换内存配置及日志级别。保存失败时原设置继续生效，可排除文件占用或目录权限问题后重试，无需依赖重启撤销本次修改。
- 主配置不可读或 JSON 损坏时停止启动；主配置缺失但已有副本、旧版固定临时文件或采集端目录时也停止启动。不会自动启用上一版计划。旧版纯本机归档可能从未保存过默认企业配置：只有 `archive.db` 而无上述配置恢复证据时，允许初始化并持久化默认配置，不修改已有归档。
- 先正常退出程序，将当前异常文件单独保留。优先从完整、最近的备份恢复主配置；使用 `.bak` 前应确认其时间和配置版本，恢复到独立目录验证。不要仅为消除启动错误删除归档、配置副本或密钥文件。
- 已有归档缺失访问令牌，或令牌无法由当前 Windows 用户解密时，停止启动；从同一备份恢复原 `access-token.dpapi`。令牌重新设置后的旧备份不能代表当前认证状态。

文件替换和刷盘降低写入中断风险，不能替代完整备份，也不构成物理断电时的一致性保证。

## 完整恢复与 DPAPI 边界

恢复前退出目标程序，将备份还原到新的独立目录；保留原运行目录，不对真实数据做覆盖式试恢复。先使用备份对应版本和原 Windows 用户验证，再考虑版本升级。

当前私钥、访问令牌和采集端本地配置由 Windows 当前用户的 DPAPI 保护。仅复制文件到另一台电脑、另一个 Windows 用户或重装后的环境，不保证能够解密。跨机迁移应另行设计显式授权的密钥导出与重新保护流程；当前没有该工具，不能宣称普通文件备份支持跨机完整恢复。

使用维护窗口恢复时，程序先保留 `serverData/restore-pending.json`，主服务拒绝在此状态启动；只有用户确认且安全配置保存成功后才删除标记。手动复制旧目录的恢复不会自动获得这一保护，仍须先检查计划、监听和采集端连接安排。
