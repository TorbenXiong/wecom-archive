# 本机采集与资料解析

## 采集流程

源数据库及 WAL、SHM 先复制为只读快照，解析完成或失败后清理。“包含全内容”在同一任务中完成消息、关系、图片和附件处理，再返回结果；进度显示在采集弹窗中。“仅采集文本”保留媒体消息及引用，但不扫描源媒体内容。

本次采集的脱敏选项默认取服务端配置，手动重试保留选择，不修改远程采集端配置。手机、电话、邮箱等敏感值以及工号、地址和企业扩展资料按策略显示 `[敏感数据已脱敏]`。切换选项不会还原历史脱敏内容，须重新采集已有缓存原值。

媒体目录索引按需建立：消息本地路径可用时直接校验文件，只有名称或摘要回退查找时才递归建立通用索引，并在本次采集中复用。没有附件的增量周期不建立媒体索引；语音摘要查找仅遍历已授权 Voice 相关分支，不建立通用图片和文件索引。媒体索引不跨周期保留，下次采集可发现新下载的缓存；原有路径授权、同名歧义拒绝、遍历深度限制及语音内容复验继续生效。首次回退查找仍可能遍历全部媒体目录，不代表采集各阶段均已增量化。

快照每个周期仍完整读取 DB/WAL/SHM。可选的跨周期低写入模式通过进程环境变量 `WECOM_ARCHIVE_SNAPSHOT_CACHE=1` 显式启用，默认关闭；启用后，采集端计划从首次任务使用，工作台本机计划从带增量游标的周期使用并建立缓存。缓存位于数据目录 `snapshot-cache/`，按源账号及实际文件路径隔离，仅保留一份原始副本。缓存独占移入新的工作目录后，每个文件逐块比对源字节，只写不同的 64 KiB 块并截断旧尾部。大小和修改时间一致也不会跳过内容比对，缓存损坏或上次读取改变副本时会按源文件修复。缺失、并发占用或布局无效时回退完整复制，拒绝链接文件；不使用硬链接共享源文件或工作副本。

若复制期间文件变化而需要重试，可复用本次尚未交给读取方、复制前后及重试前长度和修改时间均一致的副本；变化、复制失败或无法获取修改时间的文件重新处理。每次检查重新发现 WAL/SHM，出现或消失均触发重试，并在读取前移除已消失旁车的旧副本。整体文件集合和元数据校验通过后才返回快照。读取完成后归还原始副本并清理工作目录，派生解密文件不进入缓存；失败工作目录也清理。Windows 私有副本的只读属性会清除，以支持重试和清理，源文件权限保持不变。缓存是可丢弃的敏感运行数据，可在停机后删除，不是完整备份。这项优化减少重复写入，仍完整读取源文件及缓存，不承诺采集总耗时的固定加速比。

合成复制对照可用已有工具链离线运行 `cargo run --release --locked --offline -p wecom-archive-server --example snapshot-copy -- 64`。仅生成临时合成文件，不发现真实账号；比较 5 次重复的原完整复制和跨周期缓存，断言每次副本 SHA-256 与源一致，输出构建快照时间和逻辑写入字节。计时不包含摘要校验、缓存归还及清理，文件系统缓存已预热，不代表完整采集、物理磁盘写入或生产 SLA。该模式同时读取源文件和缓存，减少内容写入不保证耗时下降，因此不默认启用。

2026-11-06 在 Windows x64 使用最终服务端基准入口及仓库 Release 配置，64 MiB 合成主库、每项 5 次顺序样本的结果如下。每次副本摘要及逻辑写入量断言均通过；这些数字仅代表本次预热对照。

| 场景 | 完整复制 P50 | 缓存 P50 | 完整复制内容写入 | 缓存内容写入 |
| --- | --- | --- | --- | --- |

## 消息、媒体与会话

- 富文本按片段顺序保留表情、数字、空格和重复文本；已知表情标识转换为内联表情，未知标识保留原文。应用通知卡片仅解释允许的格式，其他 HTML 保持转义。语音从 `msg_voice2text` 读取客户端已有转写，通过 `message_table.server_id = msg_voice2text.message_id` 关联；转写进入 `body_text` 供展示、搜索和导出使用。没有转写记录时保留占位，不自动执行语音识别。
- `content_type=16` 归类为语音，旧归档需要手动重新采集才能纠正类型和补充转写。“包含全内容”从消息 protobuf 字段 `10` 提取 MD5，在对应账号已授权 `Cache/Voice` 等 Voice 目录内，按 SILK 文件的完整内容摘要关联按时间命名的缓存。校验文件头、内容摘要及已知大小，匹配后沿用 SHA-256 归档；不保存远程下载凭据或字段 `8`。缺失、变化或多候选歧义时保留不可用状态，不按相似文件名猜测。
- 已采集语音可在浅蓝气泡中离线播放或暂停，显示总时长，播放后显示已播放时间；下载图标位于最左侧，转写文字位于气泡右侧，同一行保存 `.silk` 原文件，不再调用系统应用打开。解码在 Worker 内进行，WASM 资源内嵌，切换页面会停止播放并释放资源；解码失败仍可保存原文件。原始文件和归档摘要不变。播放限制为 10 MiB、10 分钟，解码超时 30 秒；不提供自动语音识别，未在本机缓存的语音仍无法离线补齐。
- 显式撤回字段标记的消息在界面显示“消息已撤回”，隐藏正文及附件操作；`2063` 事件保留为撤回通知。未验证本地事件目标结构时，不用任意数字匹配原消息，撤回关联仍有覆盖限制。归档中的历史正文和媒体继续保留，不因界面隐藏而删除。
- 图片优先按消息本地缓存路径关联原图，失效后尝试同一消息的其他缓存；补充识别 `Cache/Image`、`Emotion` 等目录。文件按原名、摘要及消息标识查找，同名歧义不任意匹配。解析不保存远程访问材料、缓存绝对路径或 OCR 数据。
- 媒体逐文件计算 SHA-256 并写入内容寻址库，所有定位路径必须处于授权目录内。外部应用打开经校验的独立副本；保存不执行文件，可执行附件打开前需确认。
- 后续仅文本采集或源缓存过期时，保留同一未变化消息已归档的媒体；同一资源摘要的语音即使转写更新也保留音频。媒体身份变化或采集到新内容时正常更新。源文件已清理且此前未归档的内容，须重新下载后采集。

| 源会话 | 展示规则 |
| --- | --- |
| `S:` | 私人会话，优先使用目录姓名 |
| `R:` | 群会话；没有群名时显示已知成员组合及归档成员数 |
| `M:` | 已核实文档元数据时显示文档会话及标题，否则显示应用会话 |
| `O:` | 个人应用会话，统一按“应用名-用户名”命名 |
| `T:` | 缺少可核实身份时显示临时会话，不推断联系人或应用 |
| `Y:` | 系统会话，缺少名称时显示系统通知 |

## 人员资料与兼容性

联系人普通列、与行 ID 绑定的 `pb_content`、带标签的企业属性及部门目录共同补充资料。名片姓名下显示企业和已配置的签名，主要字段依次为部门、职务、邮箱、工号、手机、电话、座机、归档标识、身份；其他已配置字段保留，空字段隐藏。

资料通过已有 `raw_payload.participant_profiles` 传递，并投影至 `participants.metadata_json`，不增加数据库字段。`MessageV1`、`ArchiveBatchV1`、`ClientExportV1`、`UploadEnvelopeV1` 的结构不变；人员 API 增加可选 `profile`。会话类型新增 `document`、`application`、`assistant`、`temporary`、`system` 显示语义，旧归档缺少的信息通过重新采集补齐。

本地未缓存的电话号码无法离线还原。已对联系人、企业资料及相关缓存做只读核验；一次原生名片点击“查看”前后对比没有发现可补齐该联系人的持久号码。本结论限于已核验的客户端与缓存，不能推广到所有版本。字符串 `null`、内部数字标识和企业总机不能作为个人号码。补齐按需显示的号码仍需另行确认企业授权的数据来源，当前实现不增加网络请求。

历史人工检查见 [0.0.12 验收清单](acceptance-0.0.12.md)，当前构建与验收入口见 [README](../README.md#开发)。真实数据、诊断副本及临时诊断代码不进入源码或发布包；历史诊断目录不属于交付产物。
