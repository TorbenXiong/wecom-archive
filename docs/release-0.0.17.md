## 新功能

- 工作台新增独立备份与恢复窗口，支持停服后的完整备份、文件与数据库校验，以及恢复到新目录；恢复首次启动须确认，确认后暂停计划、停用旧采集端并使用本机监听。
- 导入、本机采集和归档导出支持原任务状态查询。请求响应丢失或结果暂不可用时保留原标识，提供继续查询，避免重复上传、采集或创建导出。
- 已绑定采集端新增设备专用上传结果确认；校验身份与内容绑定一致的完成结果后才记录上传成功，结果未知时保留原标识，不推进该次增量检查点。

## 问题修复

- 一次导入的全部消息批次、会话和人员目录、修订、FTS 及统计统一事务提交，后续阶段失败时回滚数据库变更；已有附件重新核对大小和实际 SHA-256，拒绝静默接受损坏文件。
- 归档与快速本机导出按数据目录共享输出名额，独立目录互不阻塞；输出队列异步等待，后台归档导出排队时支持取消，请求等待中断不提前释放运行锁或处理资源。
- 后台导出终态保留一小时；64 条记录额度已满时明确拒绝新任务，保留原结果和成品，不再为新任务提前挤掉仍可查询的结果。
- 工作台和采集端精确匹配 HTTP 状态与已知业务错误码；其他不确定响应继续确认原任务，不因错误码存在或状态不匹配就丢弃待确认标识、允许误重传。

## 下载

下载并运行 Windows x64 单程序 `WeComArchive.exe`。升级前正常退出旧程序，替换 EXE，并保留原有 `serverData/`、`collectorData/` 和 `source-roots.dpapi`。新目录首次运行由程序生成运行数据。

本版本保持数据库 v2 和四个归档契约兼容，第三方依赖未变，无需为本次可靠性改动重新采集。完整 JSON 导出不包含服务端附件字节，不能替代完整备份；数据库与媒体文件不是联合原子事务，数据库阶段失败仍可能留下未引用附件。

完整备份应保留随备份保存的程序，先使用对应版本和原 Windows 用户恢复，再升级。DPAPI 凭据仍受用户及机器环境限制，普通文件复制不保证跨用户或跨机完整恢复。任务记录及采集端待确认标识仅存进程内存，当前不提供关闭页面或重启后的自动任务恢复；结果不存在也不能证明原操作已回滚。进程中断和隔离磁盘写满演练不构成物理断电耐久性或真实跨机网络故障保证。

操作与边界见 [备份与恢复](backup-recovery.md)、[导入可靠性](import-reliability.md)、[长任务状态与超时协调](long-tasks.md)、[采集端上传结果确认](collector-upload-confirmation.md) 和 [导出排队与目录隔离](export-queue.md)，最终构建及验证范围见 [0.0.17 验收记录](acceptance/0.0.17-results.md)，构建和验收入口见 [README](../README.md#开发)。
