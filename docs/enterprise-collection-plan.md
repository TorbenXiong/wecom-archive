# 企业版离线加密收集规划

状态：planned。当前只完成企业版命名和设置页规划说明，没有开放加密配置、生成收集端或导入密文。普通版导出的 JSON、CSV、HTML、TXT 只供用户单独使用，企业版不接收这些文件；后续企业版只接收其专属采集端生成的加密数据。

## 产品流程

1. 管理员在企业版创建组织加密配置，关联组织标识、密钥标识/版本、接收公钥、采集范围和告知文案。
2. 企业版根据配置生成专属 Windows 员工收集端。程序携带经签名校验的公开配置和加密公钥；解密私钥留在企业管理的服务端安全存储中，不进入应用包、前端页面或日志。
3. 员工运行收集端，查看组织身份、数据用途、采集范围并明确授权，再按现有只读快照流程采集。默认离线，输出加密包；加密失败必须终止，不能降级成明文导出。
4. 管理员将加密包导入企业版。服务端根据组织与密钥版本选择解密信息，先校验包大小、格式和密文完整性，再解密、校验原始归档契约并执行幂等导入，记录脱敏审计。

普通版继续提供本地 JSON、CSV、HTML、TXT 导出。专属员工收集端独立限制为加密导出，不能仅靠隐藏普通版格式选项实现限制。

## 边界与兼容性

- 企业传输加密密钥与企业微信源数据库密钥是两套用途不同的密钥，企业版不接收员工源数据库密钥。
- 新的离线加密包需要单独版本化设计；保持 `MessageV1`、`ArchiveBatchV1`、`ClientExportV1` 和 `UploadEnvelopeV1` 现有字段语义不变。实施前评审包格式、迁移及错误码，不把现有 JSON 冒充加密文件。
- 密钥标识用于轮换和历史包解密；旧私钥保留、备份、恢复和撤销策略由企业明确配置。丢失私钥后的历史包恢复能力必须在产品中明确。
- 生成端仅封装经过验证的模板和组织配置，不开放 WebView 通用 shell 或任意路径访问；构建依赖、加密依赖和应用签名方案实施前单独评审。
- 解密后的暂存数据要受控访问并在失败时清理；错误、日志和测试均不得输出私钥、真实聊天或私人路径。
- 远程上传是独立后续能力，需要产品配置、员工授权和用户启用；离线加密包不隐式开启网络。

## 分期验收

1. 加密配置：配置持久化、权限隔离、公私钥生命周期、轮换/备份与审计。
2. 员工收集端生成：组织配置签名校验、离线运行、明确授权、只读采集、仅密文导出。
3. 加密导入：正确密钥成功，错误组织/密钥、篡改、截断、重复包均按预期处理；失败时不落入归档库。
4. 发布前验证：大数据量/低内存、应用包签名、密钥轮换与历史解密、敏感数据清理。
