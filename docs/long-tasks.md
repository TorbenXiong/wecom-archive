# 长任务状态与超时协调

工作台的导入、本机采集和归档导出现在可以在请求响应丢失后继续查询原任务。连接错误、单次状态查询超时和列表刷新失败，不再直接作为任务失败或取消的依据。

## 使用行为

- 导入显示当前阶段、已接收字节数和等待时间；本机采集继续显示原有采集进度。后台分别记录排队、接收、执行、成功或失败状态。
- 请求响应丢失时，工作台自动查询同一任务。连续状态查询失败达到预算后显示“结果暂未确认”，保留原任务标识，阻止直接重复提交；“继续查询”只读取原任务。
- 导入和采集可以显式“结束跟踪”。该动作只关闭本页状态显示，不会取消后台任务；再次执行前应先核对归档。幂等合并仍保护重复消息，但不应主动重复发送正在执行的大包。
- 导出查询和取消请求遇到短暂故障会有限重试。结果未知时保留任务标识及取消意图，弹窗显示“继续查询”，选项保持锁定；继续查询不会创建新的导出。
- 任务已完成但刷新归档列表失败时，提示“已完成，但列表暂时无法刷新”，保留已确认的完成结论。

## 后台生命周期

本机采集的运行锁覆盖完整采集和归档提交，归属独立后台任务。HTTP 请求被取消后，后台仍持有运行锁，其他采集请求会被拒绝，直至原任务完成。原先锁随请求提前释放、阻塞采集线程却仍运行的路径已修正。

带任务标识的导入由独立任务接管排队、接收和处理；导入名额由原操作持有到后台处理及清理结束。连接实际中断导致文件流不完整时，仍执行现有接收失败、超时和临时文件清理规则；接收完成后的请求中断不会丢失后续处理或最终状态。任务 observer 在业务结果、资源释放和错误收敛完成后保存最终结果，再返回原 HTTP 响应；后台 panic 也会形成可查询的失败状态。

归档导出和快速本机导出改为共享本数据目录的输出名额，独立目录互不阻塞。排队异步等待，不占阻塞工作线程；后台任务排队和同秒文件名等待均支持取消。输出线程持有名额及目录锁到收尾结束，快速本机导出的采集与输出也由独立任务贯穿持有，HTTP 等待中断不会丢失后续输出。详见 [导出排队与目录隔离](export-queue.md)。

源数据读取仍使用原来的只读快照流程，导入仍使用统一数据库事务；不强制终止正在写数据库的线程。没有新增接收后取消导入、断点续传或事务与媒体库之间的联合提交。

## 兼容接口

现有导入、本机采集及导出的请求与返回结构保持兼容。工作台为一次操作预先生成 UUID，经可选 `X-Archive-Task-Id` 请求头传入；没有该头的旧客户端沿用原行为。归档契约、数据库结构和依赖不变。

新增 `GET /api/v1/tasks/{task_id}` 仅接受工作台访问令牌，返回导入或采集的 `taskId`、`kind`、`status`、`stage`、`receivedBytes`、开始/更新时间、最终结果或脱敏错误。状态记录不保存消息、文件名、源路径、附件或凭据。相同标识重复登记返回 HTTP 409 / `TASK_ALREADY_EXISTS`，不再次消费上传或创建任务；非法 UUID 返回 HTTP 400。

归档导出仍使用原来的 `/api/v1/exports/{task_id}` 状态与取消接口，创建入口也支持该可选头。因而创建响应丢失时仍保留已知标识；重复创建不会覆盖原任务。旧服务端不识别此头时，正常响应仍使用其返回的任务标识；原同步导出接口的 HTTP 404 回退保留。

远程采集端设备身份不允许登记工作台任务记录，也不能查询这些结果；不带该头的既有设备上传接口照常工作。

## 导入和本机采集的响应判定

错误码本身不能证明归档操作没有执行；带码的超时、冲突或 5xx 也可能来自已经转发请求的网关。以下三个入口每次只发送一次 POST，并通过 `X-Archive-Task-Id` 携带预生成标识。原响应不确定时，只查询同一标识的 `GET /api/v1/tasks/{task_id}`，不重新上传原文件或发起第二轮采集。

| 操作 | 请求 |
| --- | --- |
| JSON 导入 | `POST /api/v1/imports/json` |
| 加密 `.wca` 导入 | `POST /api/v1/imports/enterprise` |
| 工作台本机采集 | `POST /api/v1/collections/local` |

下列确切状态与错误码组合直接返回原业务错误。部分响应发生于登记之后，不能统称为登记前拒绝。

| 状态与错误码 | 含义 |
| --- | --- |
| `503 / TASK_CAPACITY_REACHED` | 任务记录容量不足，本次任务未登记。 |
| `409 / LOCAL_COLLECTION_RUNNING` | 另一项本机采集正在运行，本次请求未登记。 |
| `503 / IMPORT_BUSY` | 已登记的导入未取得处理名额，没有进入归档处理。 |
| `408 / IMPORT_RECEIVE_TIMEOUT` | 已登记导入未完整接收，接收失败并清理本次临时文件。 |
| `409 / BATCH_CONFLICT` | 服务端确认导入批次冲突，按既有统一事务规则失败。 |
| 其他带错误码的常规 4xx，排除 408、409、429 | 保留权限、参数、格式或当前能力等明确业务错误。 |

`TASK_ALREADY_EXISTS` 表示原标识已登记，应查询原任务。除上表外，带码或无码的 5xx，以及含义无法确定的 408、409、429，都转交原任务查询；例如 `503 / UPSTREAM_TIMEOUT` 和 `500 / ARCHIVE_STORE_FAILED` 不会仅因包含错误码就被视为最终失败。`ARCHIVE_STORE_FAILED` 可发生于不同阶段，不能据此断言事务必然回滚。

查询核对任务标识、类型和状态，只有 `completed` 才返回已确认结果，只有明确的 `failed` 终态才显示该任务的原业务错误。无权限、记录不存在、服务端重启或查询预算耗尽，都不能证明原操作没有执行或已经回滚。

旧服务端没有状态接口时，健康的原 POST 仍继续等待；已知的忙碌、接收超时和批次冲突直接保留原业务错误。若原响应已经不确定且旧端无法查询，工作台保留未知结果。应先核对归档，再决定是否“结束跟踪”或重新操作；结束跟踪不会取消后台任务。

## 超时预算

| 阶段 | 预算及结果 |
| --- | --- |
| 导入等待名额 | 服务端 60 秒；超时返回 `IMPORT_BUSY`，没有进入归档处理。 |
| 导入接收 | 服务端连续无有效数据 60 秒、接收总计 30 分钟；到期失败并清理本次接收文件。空帧不延长空闲预算。 |
| 导入/本机采集处理 | 沿用实际处理时长，不用前端固定总时限强杀采集或数据库线程；状态查询与原响应并行。 |
| 导入/采集状态及旧采集进度查询 | 每次 30 秒，读取响应体也受该预算约束；查询临时失败不改变服务端任务状态。原响应已不确定或手动续查时，连续 3 次失败后返回 `TASK_STATUS_UNKNOWN`，保留任务标识及类型。 |
| 原响应仍健康、旧服务端没有任务查询 | 继续等待原响应，查询失败不会自动重传操作或提前判定失败。 |
| 导出创建 | 30 秒；创建响应丢失后保留预生成标识，允许继续查询原任务。 |
| 导出状态及取消 | 每次 30 秒；网络、5xx、408 或 429 故障最多尝试 3 次。取消响应丢失可安全重发，只有明确终态才提示取消完成。 |

查询成功会重置连续失败计数。完成后停止本次轮询、清理计时器并中止不再需要的前端请求；请求中止不意味着撤销已经完成或仍在运行的后台操作。权限错误、记录不存在和耗尽重试预算都不能证明原任务失败。

## 保留与未覆盖边界

导入/采集的在途状态与热记录在当前进程保存，终态在内存保留 1 小时。最多保留 128 条热记录；额度包含未过期终态，达到上限时新登记返回 `TASK_CAPACITY_REACHED`，保留已有记录。管理任务现在另有持久账本：内存过期或重启后，原查询接口可读取已保存结果；重启前未确认终态的任务返回 `unknown`，不能据此断言回滚。没有持久记录时仍返回 `TASK_NOT_FOUND`。

后台归档导出最多保留 64 条热记录，包括保留 1 小时的终态；满额时拒绝新登记。过期只清理内存记录，不删除成品或持久结果；原查询接口可以回读持久记录。刷新页面、关闭窗口或重启后可在任务中心查看历史，但不会恢复原执行线程或原弹窗。相同 UUID 不因内存过期而允许重新执行。详见 [归档健康与任务中心](archive-operations.md) 和 [导出排队、结果与容量](export-queue.md)。

远程采集端现已提供独立的设备上传结果接口：响应丢失后查询原上传，结果未知时保留标识且不推进增量进度；新接口上传预算为 32 分钟，旧端回退保留 300 秒，心跳预算不变。设备隔离、续确认、容量及重启限制见 [采集端上传结果确认](collector-upload-confirmation.md)。快速本机导出、独立维护窗口的备份/恢复沿用现有同步命令，不使用本页 HTTP 任务查询。
