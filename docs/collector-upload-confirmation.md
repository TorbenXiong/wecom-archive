# 采集端上传结果确认

已绑定采集端上传加密包时，现在区分“文件已接收”和“归档已完成”。请求超时、响应丢失或查询暂不可用时，采集端保留原上传标识，显示“上传结果待确认”；继续确认只查询原上传，不重新发送该包。只有收到身份与内容绑定一致的完成结果，才把上传作为成功返回。

## 操作与增量进度

- 上传过程中显示能力检查、加密文件上传、等待确认及校验归档等阶段。
- 点击“继续确认上传”后，若原上传已经完成，直接返回该上传的完成时间及计数，不再读取或上传旧的本地采集结果。原上传来自定时任务、尚未发布本地采集结果时也使用同一行为。
- 定时采集先确认尚未结束的上传，再发现和读取源数据。结果仍未知时，本轮不进入新的采集与发送。
- 上传结果未知或明确失败均不推进该次增量检查点；本地普通采集成功、配置失效或其他错误也不会隐藏仍然存在的待确认上传。
- 待定上传后来确认成功后，定时任务仍从已持久化的旧检查点保守扫描。新的扫描可能再次包含已归档的逻辑消息，由既有幂等合并处理；确认旧结果本身不会补写当时未提交的检查点。
- 当前进程缓存最近一项已确认回执。相同配置范围、导出标识及明文摘要的包可复用回执，避免再次发送。
- “最近上传”条数使用服务端已确认的插入、未变和修订数量之和；不把本次条数当作累计指纹数量。定时任务确认旧上传后先记录已证实的成功，再开始新扫描，新扫描失败不会抹去该完成时间。

手动采集和上传的运行锁及完成状态由后台工作线程持有。WebView 命令等待被中断时，原线程继续持锁至准备、上传和确认结束，其他采集或上传不能并发进入。

## 独立设备接口

新接口使用独立的 `collector-upload.v1` 状态结构，不改变 `MessageV1`、`ArchiveBatchV1`、`ClientExportV1`、`UploadEnvelopeV1`、数据库结构或既有上传接口。

| 请求 | 行为 |
| --- | --- |
| `POST /api/v1/collector-uploads/{upload_id}` | 登记并接收本次加密包。`upload_id` 必须为非空 UUID。完整接收、同步并完成接收文件后返回 HTTP 202；202 仅确认接收，归档结果仍须查询。 |
| `GET /api/v1/collector-uploads/{upload_id}` | 查询该设备的原上传，返回排队、接收、执行、完成或失败状态，以及阶段、接收字节数、最终导入结果或脱敏错误。 |

POST 必须携带 `X-Collector-Export-Id` 和 `X-Collector-Content-Sha256`。前者为包的导出 UUID，后者为包内 `plaintext_sha256` 的 64 位小写十六进制摘要，不能用导出对象的 `content_sha256` 替代。服务端在解密前核对外层标识和摘要，再校验解密后的导出标识及已有完整性约束；不一致不会进入归档写入。

接口每次使用已绑定、未停用且未吊销的设备凭据鉴权，记录所有者由凭据确定。工作台令牌不能调用此接口，设备也不能查询工作台 `/api/v1/tasks/{task_id}` 记录。不同设备即使使用相同上传 UUID，记录仍独立；查询其他设备的标识返回 `COLLECTOR_UPLOAD_NOT_FOUND`。

相同设备重复登记原 UUID 返回 HTTP 409 / `COLLECTOR_UPLOAD_EXISTS`，不消费新请求体，不覆盖原记录。客户端据此查询原上传。完整接收后的 HTTP 请求取消不会停止后续处理；如果连接中断导致文件流不完整，则仍按接收失败、超时和临时文件清理规则结束。

## 预算与失败分类

| 阶段 | 预算与处理 |
| --- | --- |
| 新接口上传 | 连接 15 秒，总计 32 分钟，覆盖服务端最长 60 秒排队、30 分钟接收并留出余量。 |
| 服务端接收 | 连续无有效数据 60 秒、接收总计 30 分钟；沿用导入接收限制。 |
| 能力探测与状态查询 | 连接 10 秒，单次请求最多 30 秒；确认阶段还受剩余确认预算约束。 |
| 一轮结果确认 | 最多 5 分钟，通常每秒查询；连续 3 次查询失败后保留未知结果。有效的进行中状态重置连续失败计数。 |
| 旧接口上传 | 保留连接 15 秒、总计 300 秒。 |

请求发出前的校验、临时文件写入或 curl 启动失败，能够确认未发送，清除本次待确认标识，返回普通上传失败。curl 已启动后的传输、管道或响应解析失败按可能已发送处理；新接口仅继续查询原 UUID，不自动重 POST。只有确切的 `400 / INVALID_QUERY`、`401 / UNAUTHORIZED`、`403 / COLLECTOR_IDENTITY_REQUIRED`、`503 / COLLECTOR_UPLOAD_BUSY` 作为登记前拒绝清除待确认状态；相同错误码搭配其他状态不能证明请求未接受。身份、内容绑定一致的服务端失败终态也可结束本次待确认状态。

查询结果的协议版本、上传 UUID、导出 UUID、明文摘要和最终结果中的导出 UUID 必须一致，完成时间也必须有效。记录不存在、过期、权限失败、结果格式异常、绑定不一致或确认预算耗尽，均不能证明原归档已回滚；采集端保留待确认状态和标识。状态查询的鉴权失败不调用心跳的设备吊销处理，也不会据此退出采集端。

## 容量与保留

设备上传记录使用独立于工作台任务的容量：服务端总计最多 4096 条、每设备最多 64 条、每设备最多 2 项活跃上传。记录额度包含未过期终态；达到上限时，新登记返回 HTTP 503 / `COLLECTOR_UPLOAD_BUSY`，已有记录继续保留。

终态保留 1 小时，活跃或无法判定终态的记录不按时间清除。GET 只检查所查询记录是否过期，新登记时再清理过期终态。服务端记录和采集端待确认标识、最近回执均只保存在各自进程内存中，尚无持久任务账本或重启后的自动恢复。

服务端重启或记录过期后，采集端不能再用查询结果确认旧上传，应先核对归档。采集端重启会丢失待确认标识；既有增量检查点仍保留，但再次扫描可能幂等重复导入已经完成的内容，不提供跨重启的零重传保证。

## 旧服务端与配置变化

采集端先探测同一产品地址下的设备结果接口。不支持该接口的旧服务端继续使用既有 `/api/v1/imports/enterprise` 上传路径，保留原请求体和旧超时预算。旧端正常完成响应仍须匹配导出标识并包含有效完成结果；响应丢失后，由于旧端没有结果查询能力，当前进程保留未知结果，阻止自动再次上传。应先核对归档，重启采集端后再决定是否重试。

待确认上传绑定完整上传地址和设备令牌的摘要，不保存凭据原文。配置变化后，不向旧目标发送查询，也不把旧上传当成新配置下的成功；应先核对旧归档，再重启采集端使用新配置。

新增请求仅用于已配置并授权的产品上传路径，仍遵守采集端默认离线边界。鉴权头通过匿名管道交给现有系统 curl，不写入命令行或临时文件；查询不创建请求体临时文件，不跟随重定向。状态元数据不保存消息、附件、文件名、源路径、明文或密钥。

本功能不包含断点续传、接收后取消导入、强制中断数据库写入、跨进程任务持久化或物理断电耐久性承诺。接口与本机合成故障回归不能替代真实远程环境、原生桌面和 Release 交付包验收。工作台自身的长任务查询见 [长任务状态与超时协调](long-tasks.md)。
