数据库比较覆盖消息、批次、目录、修订、FTS 与 shadow 表、映射、统计、审计和序列，并执行 SQLite 完整性、外键和 FTS 完整性检查。文件比较忽略 SQLite 瞬态 WAL/SHM 及工作台锁；主数据库和其他持久文件仍逐字节哈希比较。

常规回归结果：`archive-store --lib` **28 passed / 2 ignored**；`wecom-archive-server --lib` **68 passed / 2 ignored**。默认忽略的子进程 worker 已由父测试实际启动并终止；另外两个需要管理员虚拟磁盘的写满测试，在用户明确允许 UAC 后通过 `-BoundedVolume` 分别执行，均 **1 passed / 0 ignored**。

管理员成功运行于本地时间 13:27:03–13:27:34（UTC+8），约 31.3 秒；入口复跑三个默认故障测试，随后完成实际 NTFS 写满的两个测试，最终退出码 0。三个填充阶段记录的填充文件长度均为 **238,026,752 字节（227 MiB）**，均为实际卷分配失败，不是 SQLite 页数上限或手动返回模拟错误。

本次实际运行还修正了演练脚本的两处 Windows 兼容问题：DiskPart 忽略 UTF-16 输入、返回零但未创建映像，改为本机 ANSI 编码并拒绝不可表示路径，创建与挂载合并为一次调用；`Get-Disk` 的 `BusType` 经 PowerShell 适配后为显示字符串，改读 CIM 原始数值 15。两次前置失败均停在格式化之前，已卸载、清理本次隔离目录，没有放宽磁盘身份检查。

两包 `clippy --all-targets -- -D warnings`、Rust 格式检查、PowerShell 语法检查及差异检查通过。
