## 真实环境用例

用户明确要求补跑剩余测试，并确认企业微信已就绪及存在语音样本后执行。原默认忽略的五个用例本轮分别显式执行，全部通过：

1. 当前用户本机源目录及媒体目录发现。
2. 可信企业微信进程的只读密钥探针与源数据库验证。
3. 只读采集包含群元数据。
4. 只读采集包含媒体引用及流式媒体处理。
5. 在授权的本机 Voice 缓存中选择一个有效 SILK 样本，校验资源摘要、媒体归档元数据与内容一致性。

源数据沿用只读快照流程。真实用例输出仅保留测试名称、通过数、退出码和耗时；未保存聊天正文、账号、密钥、源路径、真实音频或截图。本轮结束时真实采集工作目录为空。

## 导入超时与恢复

在最终 Release 实例中以真实墙钟计时约 60,017 ms，四组检查通过：

| 检查 | 结果 |
| --- | --- |
| 上传非空首段后停止发送 | HTTP 408 / `IMPORT_RECEIVE_TIMEOUT`。 |
| 一个上传持续发送非空数据，另一个等待名额 | 等待者 HTTP 503 / `IMPORT_BUSY`。 |
| 超时或断开后重试 | 本次临时文件清空，后续导入可继续，重复导入新增 0、未变 1。 |
| 慢上传期间访问健康接口 | 服务端继续响应。 |

六组恢复检查通过：

1. 在合成主实例强制退出后制作完整目录副本，16 个文件的清单及哈希一致。
2. 重启原实例，消息/会话数、修订号及配置不变，原访问令牌仍有效。
3. 重启后重复导入保持幂等。
4. 在恢复副本中模拟配置截断，再从 .bak 显式恢复，组织及密钥身份不变。
5. 同机同 Windows 用户启动完整恢复副本，消息与媒体计数一致、附件字节一致，DPAPI 令牌可用。
6. 恢复实例正常退出并关闭服务。

临时验收脚本的首次运行曾因页面就绪及退出连接关闭的时序而失败；补齐等待条件后完成上述复验，初次结果保留在本地验收目录。产品代码未因该脚本时序问题发生变更。
