# 导出排队与目录隔离验收（2026-11-07）

范围为 `fix/export-directory-lock`，基于 `35fc06c`。本轮处理上次验收记录中的导出全局锁竞争，保留导出命名、内容格式、授权和请求/响应结构，不调整依赖、锁文件或数据库。上述验证执行时未提交、推送、发布或生成交付包。

## 修正与兼容边界

- 删除进程级 `EXPORT_FILE_LOCK`，改为每个服务端 `AppState` 持有单许可 `export_slots`。生产服务已通过 `workspace.lock` 独占数据目录；同目录状态克隆共享许可，独立目录不占用对方名额。
- 后台归档、旧同步归档和快速本机导出共用本目录的输出许可。等待许可使用异步队列，不再占据阻塞线程；输出 worker 持有许可及数据目录锁到写入与清理完成。
- 后台归档任务排队时可通过取消通知退出，不必等待正在输出的任务归还许可。取得许可前后均核对取消标记；同秒文件名冲突按 100 毫秒间隔重试时也核对取消，既有文件不变。
- 快速本机导出保留先采集、后等待输出名额的次序，以独立任务贯穿两阶段。旧同步归档也由独立任务持有完整排队和输出流程，避免取消 handler 等待后丢失原本会继续完成的文件。
- 文件名继续采用原时间戳格式，保留 `.partial` 独占创建、完整校验和原子不覆盖发布。同目录输出仍串行，不声称固定耗时或吞吐提升。

行为说明见 [导出排队与目录隔离](../export-queue.md)。历史超时记录保留在 [采集端上传确认验收](collector-upload-confirmation-2026-11-07.md)，不改写为本轮已经执行的验证。

## 确定性回归

1. 使用仅有 **1 个阻塞 worker** 的独立运行时，固定持有目录 A 的许可，证明目录 B 的真实导出 handler 仍能完成。A 的克隆状态保持排队，取消 A 时不释放原许可也能形成取消终态；释放后可独立重试。
2. 同一状态及其克隆连续导出，确认文件名不同、两个 JSON 均完整有效、哈希一致，第一次文件字节保持不变，无 `.partial` 遗留。
3. 在当前及随后 10 秒的候选名称放置合成 sentinel，强制任务进入文件名冲突等待；取消后所有既有文件字节不变，无新成品或临时文件，许可归还。
4. 合成本机采集回调通过屏障受控等待。取消 handler、丢弃调用方状态后，真实临时目录的 `workspace.lock` 仍被持有；采集放行后先等待输出许可，再完成有效 JSON，最后可重新取得目录锁。
5. 对旧同步归档 handler 实际 poll 一次后丢弃等待者及调用方状态。持有输出许可时没有成品、目录锁仍占用；归还许可后后台完成有效 JSON，无临时文件，许可及目录锁均恢复。

所有等待均有界，使用单条合成消息、临时目录、实际导出 handler 和已有文件校验，不依赖大数据吞吐或人为降低并发负载。
