范围为 `0.0.16` 发布之后的备份恢复、导入事务、任务续查、采集端上传确认、导出队列与结果保留，以及发布前发现的响应分类修正。本页汇总累计证据，替代各功能重复的阶段性报告；真实备份及存储故障的详细记录单独保留。不同日期、程序和测试层次的结果不重复累加。

## 发布前复验

2026-11-08 完成文档精简和独立代码审阅。设备上传原先只按错误码清除待确认标识，没有核对 HTTP 状态；服务端已接受上传、网关却返回不匹配的 5xx 时，原 UUID 可能丢失并允许重传。新增两项基线红测复现，再改为仅对四种确切登记前拒绝清除标识，其余继续查询原上传。

新增 3 项实际 curl/回环 HTTP 合成回归覆盖 27 种不确定状态与错误码组合、连续状态失败后保留 pending、再次上传只续查原 UUID、恢复后复用回执，以及四种明确拒绝后可合法新尝试。上传模块 **15/15 通过**。独立审阅未发现其他阻塞项；没有修改设备协议、第三方依赖或服务端接口。

## 验证边界

- 真实专项是本机原生界面和受控响应故障，未验证真实跨机网关或网络断连。设备上传回归使用合成数据与回环 TCP/curl，不是远程部署实测。
- 媒体条目数不是逐个核验的文件数；媒体保留比较概要。图片只验证选定样本。JSON 往返限选定会话，不代表整库或真实 `.wca` 全量往返。
- 缓存只证明部分文件身份跨周期保留，不证明全部命中率或性能提升。64 条容量场景不是 64 项并发导出。
- 任务记录及采集端待确认状态仅存内存；没有页面刷新、关闭或重启后的自动任务恢复，也不承诺跨重启零重传。记录不存在不能证明回滚。
- 不提供物理断电、操作系统崩溃、磁盘缓存丢失或撕裂写耐久性保证；WAL + `synchronous=NORMAL` 的限制继续适用。
- DPAPI 仍要求同机同 Windows 用户；跨用户/跨机恢复、在线备份、断点续传、接收后取消及 HTTP/加密包上传全过程写满未覆盖。数据库与媒体库不是联合原子事务，失败可留下未引用附件。

使用及接口边界见 [备份恢复](../backup-recovery.md)、[导入可靠性](../import-reliability.md)、[长任务](../long-tasks.md)、[采集端上传](../collector-upload-confirmation.md) 和 [导出](../export-queue.md)。
