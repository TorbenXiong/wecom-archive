# 0.0.8 验收重点

请在 Windows x64、全新的可写目录中运行验收包。不要把真实数据、账号或密钥放入包目录；若测试真实企业微信数据，请先确认已经授权，并确认程序读取的是只读快照。

## 1. 启动与隔离

- 双击 `WeComArchive-0.0.8.exe`，工作台能打开，退出后进程和本机服务能结束。
- 包目录只产生预期的 `serverData/` 等运行目录；程序没有自行访问外部网站、遥测地址或远程字体。
- 重新复制 EXE 到另一个空目录启动，配置和数据边界符合预期；不要把前一个目录的 `serverData` 混入首次启动测试。

## 2. 归档浏览性能

- 载入有较多会话的归档，检查会话列表能快速显示消息数、附件数、最近消息时间和参与人。
- 打开大群会话，切换正序/倒序、每页大小、首页/末页和中间页；确认排序稳定，同一时间按稳定消息 ID 排序。
- 从全局搜索结果打开一条消息，确认进入正确会话、页码正确、目标消息被定位。
- 用稀有词、常见词、零命中词、中文/英文组合词搜索；确认结果数量、排序、会话名称、发送人和引用消息正确。
- 用附件文件名搜索，测试同一附件被多条消息或多个 ordinal 引用时不重复返回消息。

## 3. 导出正确性与性能

- 对当前会话、当前筛选、选定会话、日期范围和整个归档分别导出 JSON、CSV、Markdown、HTML。
- 每种格式各测试：简化/完整、脱敏开关、美化开关、会话升降序、消息升降序。
- 检查导出文件可打开，消息数和缺失媒体数与界面一致；CSV 中以 `=`, `+`, `-`, `@` 开头的文本不会成为公式。
- 检查正文换行、中文、HTML/Markdown 特殊字符、附件名、引用消息和隐藏公告上下文；脱敏结果不暴露账号、密码、令牌或联系方式。
- 在导出期间取消或制造失败，确认 `.partial` 会清理；目标文件已存在时不会覆盖；成功文件完整发布。
- 对 10 万条以上归档记录导出准备耗时和内存，确认进程不会随着导出持续无界增长。

## 4. 本机采集与离线边界

- 在已授权且运行中的企业微信环境，用自动发现目录执行文本采集；确认源数据库、WAL、SHM 先复制到工作目录，原始目录不被修改。
- 测试含媒体和不含媒体两种模式；检查媒体缺失只记录元数据，不让整批失败。
- 给出无效自定义目录、根目录、网络路径和父目录跳转，确认被拒绝并保留重试输入。
- 首次空结果、重复运行、失败后重试、计划立即执行和定时执行分别验证“最近尝试”与“最近成功”。
- 默认不配置上传时，采集端保持离线；只有明确配置、授权并启用后才连接已认证产品 API。

## 5. 采集端与配置

- 工作台生成采集端 EXE，使用当前配置启动；旧采集端配置不应绕过签名、过期、回滚或撤销检查。
- 同一台机器重复启动采集端，确认只保留一个实例；心跳、撤销、密钥轮换和上传幂等行为符合界面状态。
- 工作台升级后重新生成采集端 EXE；不要用旧采集端替代新配置做结论。

## 6. 重点记录

记录 Windows 版本、CPU/内存、归档消息数、会话数、搜索词类型、导出格式、首屏/深页/导出耗时、是否出现 `.partial` 残留、错误提示和 `serverData/logs` 中的脱敏日志。不要上传真实聊天内容、账号、密钥、私人路径或截图。

本包验证过：前端资源构建、Rust 全工作区测试、Release EXE 构建和离线依赖解析。上一次性能复审建议的高频词搜索、按需搜索结果定位、游标分页和复用消息总数尚未实现，验收时请把它们当作当前基线记录，不要按“已优化”验收。
