# 导出结果保留与容量保护验收（2026-11-07）

范围为 `fix/export-result-retention`，基于 `4154d04`。本轮修正导出记录在容量满时丢失近期结果的问题，并区分明确的登记前拒绝与结果不确定的创建响应。请求/状态字段、归档契约、数据库、依赖和锁文件保持不变。上述验证执行时未提交、推送、发布或生成交付包。

## 问题与修正

- 基线回归确认：已有 64 条终态记录时，第 65 项仍被接受，原逻辑会立即删除近期终态。红测按预期失败，且先取消错误接受的新任务，避免额外写出文件。
- 现保留完成、失败和已取消的结果 1 小时，额度仍为 64 条且包含未过期终态。新登记仅清理已过期终态；满额时返回 HTTP 503 / `EXPORT_TASK_CAPACITY_REACHED`，不登记、不排队，不挤掉原结果。
- 活跃、缺少完成时间、状态未知或锁异常的记录保守保留。终态时间只记录一次，迟到进度、重复取消及重复结束不会改写结果或延长保留期；内部计时字段不进入 API 响应。
- GET 和取消仅检查目标记录是否过期。清理只删除内存记录，不删除导出文件；不存在或过期沿用 HTTP 400 / `INVALID_QUERY`，界面保留未知结果和原标识。
- 前端把容量错误作为明确的登记前拒绝；其他不确定的带码 5xx、408/409/429 响应保留原任务标识，继续查询仅 GET 原任务。旧服务端的创建入口 404 同步回退，以及明确权限拒绝和重复标识处理仍保留。

操作、容量取舍和恢复限制见 [导出结果保留与容量保护](../export-result-retention.md)。

- 新增验证使用合成数据、服务端 handler 和 mock fetch；未读取真实企业微信源，未执行真实网络中断、原生 WebView2 或 Release EXE 验收。
