# 搜索接口基准

程序经生产写入 API 生成合成归档，启动临时回环服务，通过实际认证 HTTP 测量搜索及单条消息定位。不发现源目录、读取真实账号或访问第三方服务。数据及脱敏报告位于忽略的 `target/benchmarks/`；正常退出清理本次合成归档和配置。

## 运行和测量范围

已有工具链及依赖缓存时，在 PowerShell 执行：

```powershell
./scripts/benchmark-search-api.ps1 -Counts @(1000, 100000) -QuerySamples 5
```

脚本使用 `cargo build --release --locked --offline`，不安装工具或变更依赖；默认 10 万条，支持 1,000 至 1,000,000 条。每个规模使用独立进程和临时端口，环境变量仅传给子进程。

- 半数消息在大群，其余在 500 个会话，含 20 个合成人员和同时间消息。所有正文含高频词及中文，每千条有稀有词，5% 关联附件名，不含媒体字节。
- 稀有词、高频词、中文片段、附件名、零命中和组合筛选覆盖升降序；稀有/高频另比较 `locate=false` 与兼容定位模式，单条定位独立计时。
- 每次断言全部 ID、顺序和定位偏移；错误、截断或不一致使基准失败。记录首次请求及重复样本的 P50/P95，包含新建连接、认证、查询、补全、传输、解析及断言，不含夹具和服务启动。
- 固定场景顺序并受缓存影响，首次请求不是磁盘冷缓存。默认五次的 P95 接近最大值，只用于开发对照。进程峰值工作集还包含写入和启动，不能当作搜索独占内存。

## SQL 优化及同机前后对照

按原时间和稳定 ID 排序，在非文本筛选后检查 `min(32 × (offset + limit), 4096)` 条记录；正文包含成功时跳过 FTS/附件候选，其他记录保留原 FTS 及附件名匹配。填满页才返回窗口结果，不足或深页执行完整查询；附件先筛名称再解析引用。不新增数据库结构、索引或写入维护。

同一窗口外记录在相同筛选/排序下均排在窗口之后，因此填满页时结果完整。实现不假定 FTS 行号等于消息行号，不依赖派生映射表。4,200 条自动夹具的 270 组切片另覆盖边界、组合筛选、共享附件、特殊字符、FTS 和旧只读归档。

以下为 2026-11-04、源码 `0.0.12`、Windows x64 / Intel Core Ultra 5 125H 的最终对照。优化前二进制在修改 SQL 前留存并核对哈希；两边同 Release 配置、合成规则及请求，各建独立十万条归档，每项五次样本，首屏 50 条、`locate=false`，未与测试或编译并行。单位：毫秒。

| 场景 | 降序 P50：前 → 后 | 升序 P50：前 → 后 | 优化后 P95：降序 / 升序 |
| --- | --- | --- | --- |
| 高频词 | 1,320.83 → 8.77 | 977.60 → 9.70 | 11.64 / 9.80 |
| 中文片段 | 1,112.87 → 12.40 | 933.75 → 12.29 | 12.78 / 14.35 |
| 附件名 | 441.31 → 40.15 | 515.68 → 31.64 | 48.34 / 35.45 |
| 组合筛选 | 962.03 → 123.78 | 748.13 → 115.78 | 126.64 / 122.72 |
| 稀有词 | 329.73 → 266.61 | 474.34 → 336.78 | 286.87 / 350.46 |
| 零命中 | 412.15 → 320.12 | 295.35 → 297.52 | 343.45 / 314.75 |

千条和十万条的 ID、顺序及定位断言通过。优化后峰值工作集 34.72 MiB 包含夹具和启动；没有同组优化前峰值，不计算内存改善。初始探索的另一组基线因缓存和并行条件不同，不用于上表加速比。

历史原始报告属于未入库的本地产物，随本机清理可能不再保留；复测使用上述脚本生成新报告。

## 判断边界

稀疏词和零命中仍可能扫描全库，窗口尝试会增加有界工作；其小幅差异含环境波动，不宣称稳定提速。非文本条件可能扫描更多原表索引，4,096 不是原表扫描次数上限。深页、计数、导出及高频纯 FTS 候选未获得相同幅度优化。

本次对照没有覆盖百万规模、真实数据、多客户端并发、上传、渲染或慢网络；没有将单条定位的波动归因于 SQL 改动。以上历史数字不代表当前版本重新测得的 SLA。存储与导出的测量方式见[归档基准](benchmarks.md)，构建入口见[开发与构建](development.md)。
