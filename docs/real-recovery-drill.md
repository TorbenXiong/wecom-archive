# 真实备份恢复与导入故障演练

仅在用户明确授权真实数据采集、备份和故障演练后执行（PowerShell）：

```powershell
./scripts/verify-real-recovery.ps1 -Authorized
```

入口要求现有 `target/release/WeComArchive.exe` 的版本和 Windows x64 架构符合当前项目，使用已有 Rust 工具链及本地依赖编译一个默认忽略的 Release 专用测试，避免大规模哈希受 Debug 构建影响；不下载安装工具，不修改依赖或锁文件，不自动重新构建工作台 EXE。

中断后可通过 `-ResumeRun` 指定本项目 `target/acceptance/real-recovery-*/` 中带有本入口授权标记、且已完成采集的临时目录，复用其冷归档而不重新读取企业微信。只接受本项目内符合范围和标记校验的目录；成功完成后清理该临时源目录，失败时保留它以便继续排查。该选项不会清理备份目录中的其他 `.partial`。

已有本次生成的完整备份时，还可同时指定 `-Backup`，只接受 `userData/verified-backups/WeComArchive-backup-*/` 中通过完整校验、且数据库内容与该隔离源一致的备份，避免重复生成大体积副本。

## 数据和授权边界

- 演练创建独立工作台，通过当前 Release 的已认证本机 API 采集真实消息及本地附件。企业微信源仍遵循先复制 DB/WAL/SHM 再读取的流程，消息采集开启已有脱敏选项；图片和附件仍可能含敏感内容，不将其作为可公开测试产物。
- 此入口新建隔离归档及专用设备、计划配置，不备份已有生产部署配置，不改变其归档、设备、授权或计划。生成的采集端不运行，测试计划安排在至少数小时后的时段，并在备份前停止隔离实例。
- 一份经过完整校验的真实内容备份保留在受控的 `userData/verified-backups/WeComArchive-backup-*/`，作为本次请求的本机备份。该目录及临时目录均被 Git 忽略，不加入源码或交付包。终端仅报告通用相对备份路径、计数、阶段及稳定结果码。
- 采集、恢复副本、导入请求和 WebView 配置位于本次独占创建的 `target/acceptance/real-recovery-*/`。结束或失败时先停止本次创建的实例，再检查目录范围和授权标记后清理；清理失败单独报告。完整备份保留，故障数据不保留。
- 访问令牌仅在进程内解密，用于本次实例的回环 HTTP 请求，不出现在命令行、日志、报告或明文凭据文件中。程序只连接自己创建的 `127.0.0.1` 实例，不跟随重定向。

## 验证内容

1. 采集响应成功后停止隔离实例，制作完整备份；通过生产校验链路检查文件清单、大小、SHA-256、SQLite、媒体及 DPAPI。
2. 比较备份前后原隔离归档的所有业务表内容指纹及持久文件哈希，保证演练不改变备份源；包含已提交 WAL 数据的独立快照。
3. 直接打开备份中的程序，确认不监听服务且备份内容没有改变。
4. 恢复到全新目录，比较所有数据表、配置和访问身份；恢复首次启动不监听服务，并保留待确认状态。
5. 显式确认恢复后核对计划暂停、采集端停用和本机地址，再启动独立恢复实例。
6. 使用真实消息样本构造合法导入，经生产 HTTP 接口触发后批次冲突、目录触发器写入故障及校验值损坏。比较所有表，包括修订、FTS、统计、目录和审计，避免只用消息总数判断回滚。
7. 在恢复副本中暂时破坏一份真实附件的一个字节，发送正确附件内容，确认拒绝并保留损坏文件，数据库不变；随后恢复该字节并核对完整哈希。
8. 删除故障条件后重试，确认修订成功；重复导入不增加消息或修订。检查数据库完整性、保留备份仍有效，原隔离归档仍未改变。

该入口不模拟物理断电、真实磁盘写满、跨 Windows 用户恢复或跨机密钥迁移。完整备份及导入的产品边界分别见 [备份与恢复](backup-recovery.md) 和 [导入可靠性](import-reliability.md)。
