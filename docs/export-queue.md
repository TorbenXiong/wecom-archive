# 导出排队、结果与容量

归档导出和快速本机导出按数据目录共享一个输出名额。不同数据目录互不占用对方名额；同一目录仍串行生成导出文件，保留原有文件名与不覆盖规则。

## 原因与处理

原先所有服务端状态共用进程级 `EXPORT_FILE_LOCK`。即使两个工作台使用不同的数据目录，仍会相互等待。批量导出还会持锁等待同秒文件名避重，把本目录的等待传递到其他目录；独立目录的导出测试因此可能超过自身的等待预算。

现在每个 `AppState` 持有单许可的异步 `Semaphore`，克隆状态共享该许可。生产服务创建状态前会规范化数据目录、取得并持有 `workspace.lock`；同一目录的另一个服务不能再创建独立运行状态，相对路径与绝对路径别名也受同一目录锁约束。因此无需再维护按路径注册的进程级导出锁。

异步等待输出名额不占用阻塞工作线程。取得名额后才进行归档读取、内容整理和文件输出，输出线程持有许可及数据目录锁，直到写入和临时文件清理结束。HTTP 等待中断不会提前释放仍在工作的线程所持资源。

## 共用范围与生命周期

| 入口 | 排队与执行 |
| --- | --- |
| 带任务标识的后台归档导出 | 独立任务异步等待本目录名额，取得后进入输出线程；沿用原任务的状态及取消接口。 |
| 既有同步归档导出 | 独立任务等待同一输出名额；请求等待中断后，已接受的排队或输出继续完成，输出线程持有名额至收尾。 |
| 快速本机导出 | 本机采集可先于输出名额完成，随后异步等待同一名额并生成文件；采集和输出由一个独立任务贯穿持有。 |

快速本机导出仍保持原来的直接快照导出流程，不先把消息写入归档数据库再读取。采集与输出分别使用阻塞线程，整个两阶段流程由独立任务接管；HTTP 等待在采集阶段中断后，已经启动的采集仍会继续进入输出阶段，不丢失原本应生成的文件。两个阶段的工作线程均保留数据目录锁，输出阶段还持有输出许可。

快速本机导出继续使用既有同步响应，不增加任务查询或取消接口，也不把客户端关闭等待当作取消导出。

## 取消行为

后台归档任务在排队时通过 `Notify` 接收取消通知，并在等待名额前及取得名额后检查取消标记。取消通知会保留至等待者接收，取消不需要等待当前输出者归还名额。任务仍先进入取消中状态，由后台确认结束后再形成取消终态。

取得输出名额后仍使用已有协作取消检查，不强制终止写文件线程。为避免同秒目标文件名冲突而等待时，按 100 毫秒间隔重试，并在重试前检查取消标记；不必等待文件名自然变得可用才响应取消。

取消与完成可能交错。一旦输出完成并返回成功，任务记录完成结果，随后收到的取消不能撤销已经生成的文件。

## 结果保留

每个服务端状态最多保留 64 条后台归档导出记录，生产状态对应一个独占的数据目录。额度包括排队、执行、取消中、结果未知和未过期的终态，不与导入、采集或设备上传的记录额度混用。

完成、失败或已取消的终态记录保留 1 小时，从首次确认该终态时开始计时。终态只记录一次；后续查询、重复取消或迟到进度不会改写已确认结果，也不会延长保留期。完成时间只用于服务端内存中的保留判断，不增加状态 API 字段。

排队、执行和取消中的任务不按时间清除。缺少完成时间或状态锁异常等无法明确判断结果的记录也保守保留；不能因为容量已满就把未知记录当作已结束记录删除。

## 容量满时

`POST /api/v1/exports/start` 登记新任务前清理已过期的终态。若仍有 64 条记录，返回 HTTP 503 / `EXPORT_TASK_CAPACITY_REACHED`，沿用已有错误结构并标记可恢复；本次新任务没有登记或进入输出队列，已有记录及成品不受影响。

容量包含最近一小时内的终态，因此连续结束大量任务后，即使当前没有正在输出的任务，也可能暂时不能创建新的后台导出。应先查询已知任务，并等待记录到期；不通过立即清除最近结果换取新名额。未过期的相同任务标识重复登记仍返回 HTTP 409 / `TASK_ALREADY_EXISTS`，即使容量已满也不覆盖原记录。

工作台将确切的 `503 / EXPORT_TASK_CAPACITY_REACHED` 识别为登记前拒绝，不查询未登记的新任务或回退到同步接口。其他不能证明未登记的创建错误，包括带码或无码的 5xx、含义不确定的 408/409/429，保留原任务标识并按结果未知处理；继续查询只读取原任务。旧服务端创建入口不支持任务接口时，HTTP 404 的原同步导出回退仍保留；正常响应仍以服务端确认的任务标识为准。

## 过期查询与文件

状态查询和取消请求只检查目标记录是否过期；登记新任务时再清理全部已过期终态。清理仅移除内存中的任务记录，不删除已生成的导出文件，也不修改归档数据。

目标在内存中不存在或过期时，状态接口先查持久任务账本，返回保存的结果或重启后的 `unknown`；没有账本记录才沿用 HTTP 400 / `INVALID_QUERY`。取消接口只作用于当前进程任务，过期或不存在仍返回 `INVALID_QUERY`。不能把记录不存在当作导出失败、已取消或没有成品的证明。

## 保留的边界

- 文件名继续使用原有时间戳格式；同秒冲突等待下一次可用时间，不改成随机名称或覆盖旧文件。
- 输出仍通过独占创建本次 `.partial`、完成校验后原子发布；已有目标和其他操作的临时文件继续受到不覆盖保护。
- 同一数据目录仍只有一个输出名额，长导出仍会影响本目录后续导出。本功能不提供同目录并行写入能力，也不承诺固定耗时或吞吐提升。
- 目录隔离依赖服务端现有的数据目录独占锁，不提供多个服务同时写同一目录的能力。
- 热记录保留在当前进程；管理任务历史另行原子保存，重启后可在任务中心查看。重启前未确认结果标为待核对，不自动重跑或恢复执行线程，见 [任务中心](archive-operations.md)。
- 1 小时是结果记录的保留窗口，不是执行时限。活跃或未知记录可能长期占用额度；不会强制终止写文件线程或为了腾出容量清除未知结果。
- 既有同步归档和快速本机导出没有因结果保留规则新增后台任务查询能力。请求及状态字段、文件格式、依赖、数据库和归档契约保持兼容，没有新增网络目的地。

任务查询与超时协调见 [长任务状态与超时协调](long-tasks.md)。
