# 图片按需加载

此前每张图片附件挂载时都会请求原图，即使位于当前消息页的视区外。现在使用 `IntersectionObserver` 观察图片占位，观察根为 `.message-scroll`，上下各预读 120 px。占位继续使用原有固定尺寸，滚动到图片附近时才通过原有认证媒体 API 读取内容。

点击图片可直接读取并打开预览，点击与可见性通知共用同一个进行中的请求；读取成功后，当前图片实例的内嵌显示和预览共用同一个 Object URL。失败保留可点击的重试入口；未采集内容的图片保持禁用。不支持可见性观察的环境保留点击加载，避免退回整页自动下载。

请求通过 `AbortSignal` 传递到媒体下载及响应体读取。图片从消息页卸载，或认证令牌、内容哈希变化时，取消请求、断开观察并释放已加载 URL；已取消请求即使迟到返回 URL，也立即释放，不更新页面或打开预览。内容与凭据变化使用新的图片实例，避免旧图片在同一消息位置复用。

当前页已加载的原图会保留到对应图片实例卸载，因此滚动回看及重复预览无需重新读取。遍历整页后，内存仍随已浏览图片总大小增长；本轮没有缩略图生成、跨页图片缓存或消息列表虚拟化，媒体接口、存储格式、数据库和依赖均不变。

## 验证方法

- 组件测试构造含 100 张图片的合成消息页，挂载后没有图片读取请求；只通知两张图片进入视区，恰好发起两次读取，重复通知不增加请求。
- 覆盖读取中点击、预览复用、错误后点击重试、卸载取消及迟到 URL 释放、同一消息的凭据/内容更新、内容缺失、无观察 API 环境和 React StrictMode。
- 媒体 API 测试验证取消信号传递；响应体读取结束时已取消，不创建新的 Object URL。
- 原版隔离桌面脚本新增 `image-offscreen-no-fetch`、`image-visible-load`、`image-preview-reuses-load`，使用原有合成图片，通过实际 WebView 的滚动位置、认证媒体请求次数及图片解码结果验证。

组件请求次数反映加载触发范围，不代表 HTTP 耗时或真实图片内存收益；桌面验收使用合成内容，不读取真实账号。
