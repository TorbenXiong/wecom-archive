# 进程中断与存储容量故障演练

使用现有 Rust 工具链和本地依赖，无需新增软件或依赖。默认入口（PowerShell）：

```powershell
./scripts/verify-storage-faults.ps1
```

默认使用独立合成数据，执行备份、恢复和导入进程强制终止，以及 SQLite `max_page_count` 容量限制。不读取企业微信源库，不修改已保留的真实备份。全部故障代码位于测试模块，没有产品环境变量开关或生产故障注入接口。

## 验证时点

- 备份、恢复：在本次 `.partial` 中观察到合成程序文件已开始写入后，强制结束本次创建的子进程，要求没有新正式目录发布。残留 `.partial` 校验和恢复均拒绝；在新目录重试成功，旧残留不被接管或覆盖。逐文件比较原持久数据及完整备份。SQLite 可能创建空 WAL/SHM，进程锁及这些瞬态旁车不纳入持久文件比较。
- 导入提交前：通过测试连接的 TEMP trigger，在所有批次完成、进入目录写入时暂停；缓存缩小以确保未提交脏页已经进入 WAL。父进程强制结束子进程，重新打开归档，要求所有表与导入前一致。
- 导入提交后：在导入成功返回、连接仍打开时记录所有表指纹并暂停；父进程强制结束子进程，要求重新打开后的全部表与提交状态一致。前后两种中断均检查完整性、外键和 FTS，随后重试并重复导入，要求不重复增加消息和修订。
- 容量限制：给独立数据库增加 64 页增长余量，分别在第二批次大字段及目录大字段触发真实 `SQLITE_FULL`。确保第一批次已经完成，失败后回到自动提交状态，全部表回滚，重新打开后仍一致；取消上限后重试成功。

表指纹对每个单元格编码类型、长度和值后计算 SHA-256，对每张表的行排序比较，覆盖 FTS shadow、映射、统计、修订、审计和序列。指纹不输出消息正文。

## 有界 NTFS 写满

此项需要 Windows 管理员权限，默认测试中被忽略。在管理员 PowerShell 中执行：

```powershell
./scripts/verify-storage-faults.ps1 -BoundedVolume
```

脚本先执行默认演练，再在项目 `target/acceptance/storage-fault-<随机标识>/` 中创建独占的 **256 MiB 固定 VHD**，不接受现有磁盘、映像或盘符参数。格式化前通过映像关联检查磁盘是新出现的、RAW、FileBackedVirtual、容量相符且不是启动盘或系统盘；只对该新分区分配空闲盘符。宿主盘空闲空间不足 2 GiB 时停止。测试结束尝试卸载映像，确认已脱离后再清理本次带标记的目录；卸载或清理未完成不能报告整项成功。

测试在该新卷内顺序写入并刷盘，要求 Windows 返回 `ERROR_HANDLE_DISK_FULL` 或 `ERROR_DISK_FULL`；填充量超过 512 MiB 立即失败。随后释放少量空间，让故障发生在后续写入阶段：

1. 导入：保留 256 KiB 余量，第一批次修订后在第二批次大字段增长时要求 `SQLITE_FULL`；核对全部表回滚，释放填充文件后重新打开、完整性校验、重试及重复导入。
2. 备份与恢复：各保留 1 MiB 余量，复制 32 MiB 合成程序时失败；要求没有正式发布，原文件与已有目标文件保留、本次 `.partial` 清理；释放空间后重试并校验恢复待确认标记。

这些测试使用合成数据，覆盖归档存储和维护函数，不等同于真实大数据卷或 HTTP/加密 `.wca` 上传全过程的写满验收。

2026-11-07 已经用户授权 UAC 完成本项：导入、备份、恢复均收到实际 Windows 错误 112，故障恢复和重试通过，虚拟磁盘已卸载清理。重复执行仍需管理员权限和一个全新隔离 VHD，不复用旧卷。

## 断电结论的边界

强制结束进程保留了操作系统和磁盘缓存，不能代表物理断电、缓存丢失、撕裂写或设备掉线。演练不会关闭主机电源、重启电脑或填满工作盘。

归档当前采用 WAL + `synchronous=NORMAL`。SQLite 官方说明该模式的已提交事务在操作系统崩溃或断电后可能丢失；这些进程中断测试不能证明“已确认导入永不丢失”。若产品需要更强的已提交数据耐久性，应另行评估 `FULL` 及其性能代价，并在专用虚拟机或存储故障环境验证。参见 [SQLite synchronous 文档](https://www.sqlite.org/pragma.html#pragma_synchronous) 和 [SQLite 故障测试说明](https://www.sqlite.org/testing.html#crash_testing)。
