## 本轮优化验证（2026-10-10）

服务端和归档存储已按职责拆分，公开桌面入口、版本化契约、数据库版本和迁移 SQL 保持兼容。服务端通过已有 `source-windows` 路径依赖调用 Windows 加密、DPAPI 和默认应用打开；锁文件仅增加这条 workspace 依赖关系。

Rust 全工作区 112 项测试通过，4 项真实数据测试保持忽略。前端默认并发运行时有一项分页测试触及 5 秒超时；使用 `pnpm exec vitest run --maxWorkers 1` 重跑，63 项全部通过，没有修改超时或断言。TypeScript、client/server 前端构建、Rust 格式检查和 Windows x64 Release EXE 构建通过。Clippy 完成检查，严格 `-D warnings` 仍受原有代码的警告影响。

桌面测试加载失败的原因是测试 EXE 缺少 Common Controls v6 的 manifest。构建现在由链接器自动生成旁置 manifest，避免依赖 `target/` 中手工创建的文件，应用既有的嵌入资源保持可用。

10 万、50 万和 100 万消息合成基准已完成，全部计数和 JSON、Markdown、CSV 导出校验通过；1,000 条烟测也已通过。百万规模最终包含 1,001,000 条消息，FTS 搜索中位耗时约 614 ms，但完整导出前的数据加载约需 10.64 分钟，进程峰值工作集约 5.27 GiB。基准的方法、范围和瓶颈见 [`benchmarks.md`](benchmarks.md)。

## 第三轮优化验证（2026-10-11）

会话列表改为先分页、再读取增量统计；通过会话内附件引用次数保持去重计数。FTS 修订使用消息 ID 到实际 FTS 行号的索引映射，消息触发器使旧版本写入后的映射失效，下次批次处理时统一修复。写入复用参数化语句，并按批更新会话最近消息时间。派生表在旧归档首次可写打开时事务回填，后续打开不重复扫描；只读旧 v2 归档保留兼容路径。数据库 v2、四个版本化契约和 0.0.8 版本保持兼容，没有新增依赖或修改锁文件。

Rust 全工作区 121 项测试通过，4 项真实数据测试保持忽略；新增覆盖共享附件、重复 ordinal、修订、会话投影移动、回滚、旧库回填、任意 FTS 行号、旧版本写入后修复、快照和乱序批次时间兼容。Clippy 完成检查，新增代码无警告，仍有既有代码警告。Rust 格式和差异检查通过，Windows x64 Release EXE 及 Release 基准程序构建通过。前端验证沿用第二轮的 63 项测试和 TypeScript 检查。

最新 1,000 条烟测及 10 万、50 万、100 万条最终实现基准全部完成，计数、搜索、统计和三种格式导出校验通过。百万规模最终包含 1,001,000 条消息，会话列表中位耗时从 6.31 秒降至 0.64 ms，含 100 条修订的批次从 92.75 秒降至 77.33 ms，进程峰值工作集约 28.72 MiB。代价是百万首次写入从 359.95 秒增至 384.22 秒（约 6.7%），数据库从 2,611.52 MiB 增至 2,668.11 MiB（约 2.2%）；10 万和 50 万的首次写入成本也有增加。完整对照和测量边界见 [`benchmarks.md`](benchmarks.md)。
