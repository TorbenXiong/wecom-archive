# 归档健康与持久任务中心

## 归档健康

页面默认显示校验结论与关键指标，校验明细、缺失原因和范围说明可按需展开。任务中心使用紧凑列表；任务编号、错误码、文件名和完整计数在任务详情中查看，刷新保留展开状态。

主导航的“归档健康”只读取归档与本产品数据目录，不发现或读取源数据库、不联网、不修改消息或媒体。

- 汇总消息、会话、数据源与批次数量、消息时间范围、最近批次采集时间、不支持类型，以及声明时间/会话/消息类型限制的批次。范围来自已保存的批次契约，不代表源端完整覆盖；消息时间空档不作为漏采证据。
- 媒体按记录统计，区分采集时已标记缺失、大小/哈希/读取异常；缺失原因只映射固定类别，不返回原始原因、文件名、源定位符或账号。
- 显示数据库主文件大小与数据目录所在磁盘对当前用户可用的字节数；主文件大小不包含 WAL、媒体或整体目录用量。空间读取失败显示“暂不可用”，不伪报零空间。
- 手动完整校验在一个 SQLite 只读快照内运行 `integrity_check` 与外键检查；数据库检查通过后，对标记为 verified 的媒体逐文件核对大小与 SHA-256。拒绝媒体根目录及文件链接/junction，区分归档文件缺失、内容损坏与不可读。不会补采、修复或删除文件。
- 每个工作台同时只运行一次校验。关闭页面不取消后台校验；工作台进程退出则停止。校验结果保存归档 revision，页面会提醒校验后归档发生变化。磁盘文件在校验后仍可能变化，结果不是持续监控保证。

数据库检查未通过时不继续附件扫描。无法打开数据库等基础错误记为任务未完成；校验发现损坏属于“校验任务完成但发现异常”，不能与“归档健康”混为一谈。未检查源端内容、FTS 搜索语义、未采集附件或历史采集完整性。

## 任务中心

任务范围包括工作台 JSON/加密包导入、手动/计划本机采集、采集端上传、归档导出、快速本机导出和归档校验。采集端本机尚未上传的采集、独立维护窗口备份/恢复、软件更新不在此账本范围。历史从功能启用后开始，不回填旧操作。

记录位于实际数据目录 `task-history/<UUID>.json`，复用独占临时文件、刷盘与原子替换。没有新增依赖、归档数据库表或版本化契约字段。记录仅保存任务种类、固定阶段、状态、时间、阶段字节计数、结果计数、固定错误码；导出额外保存本产品生成的文件名与摘要，不保存聊天正文、账号、原始源路径、完整输出路径、凭据或源适配器任意进度文本。

持久记录目前没有自动过期或删除功能，需将此目录纳入完整备份。任务中心按开始时间倒序，默认每页 50 条，支持类型/状态筛选及翻页；API 单页最大 200 条。页面每 5 秒读取本产品已认证 API，离开页面后停止轮询。

结果规则：

1. 接受任务前必须成功保存初始记录；保存失败拒绝登记，不开始工作。
2. 阶段变化与终态原子落盘；接收阶段不逐块刷盘，字节数只是阶段检查点。后续保存失败会在当前进程的任务中心显示明确警告，内存结果不能视为已经持久保存。
3. 重启时，已保存的完成/失败/取消结论保留；其他状态改为 `unknown`，不根据文件存在、消息数量或缺少任务记录推断成功、失败或回滚，不自动重跑。数据库提交与账本完成记录之间发生退出时，可能已经入库而账本仍未知，须人工核对。
4. 原工作台导入/采集状态接口和归档导出状态接口可以回读已保存结果。相同 UUID 的新工作台任务会被拒绝，避免重启或内存过期后重复登记。此处持久历史不表示后台线程或执行进度可跨进程恢复。
5. 采集端上传在任务中心保存独立管理记录；设备原确认接口的归属、配额、进程内保存与重启边界保持原样。管理历史不开放给设备令牌查询，也不代替设备的上传续确认协议。
6. 已完成导出的文件可能随后被用户移动、删除或修改；任务记录保存的是当时结果与摘要，不声称当前成品仍然存在。结果未知的导出可打开目录自行核对。
7. 历史目录、记录损坏或存在链接时停止启动并保留原文件，避免默默丢失去重凭据。恢复还会核对规范 UUID、任务种类、状态、时间与结果类型，缺少结果的完成记录不被视为成功。通过已有维护窗口检查、恢复完整备份；不以清空账本作为常规修复方式。

## API

全部新增接口仅接受工作台访问令牌，不增加第三方网络目的地或 Tauri 通用权限。

| 接口 | 用途 |
| --- | --- |
| `GET /api/v1/archive/health` | 聚合状态、存储空间及最近校验任务 |
| `POST /api/v1/archive/health-check` | 登记一次后台校验，返回 HTTP 202 和任务记录 |
| `GET /api/v1/task-history?kind=&status=&offset=0&limit=50` | 过滤并分页读取管理任务历史，包含写盘异常标志 |

首次校验请求响应丢失时，应先刷新健康页或任务中心，确认已登记任务后再决定是否操作；重复运行中的校验会被拒绝。历史只提供查询和现有归档导出取消能力，不提供一键重跑或强制终止导入/采集。
